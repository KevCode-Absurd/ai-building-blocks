

The outbound messaging pipeline: Block Kit formatting, response filtering for client data protection, numeric claim validation, and the separation between agent output and Slack presentation.Response Validator ChecklistRun every agent response through these 12 checks before posting. Most of these are automated in the agent pipeline. If you are building your own, wire each one in.The 12 checks1. No PII leaksNo email addresses, phone numbers, credit card patterns, or government IDs in the response. Regex scan. If a match is found, either redact (****) or refuse to post.2. No API keys or tokensScan for known key prefixes: sk_live_, xoxb-, xoxp-, eyJ, Bearer . If found, refuse to post and log a security event immediately. Rotate the exposed credential.3. No other-client data (strict channels)The response must not name any client other than the one the current channel belongs to. Maintain a cached list of all client names and scan for matches. If a foreign client appears in a strict-enforcement channel, strip that section and log the event.4. No internal financial commentaryPatterns to reject in client-facing channels: "our margin", "our markup", "our fee", "internally we", "our costs", "profit". These belong in internal channels only.5. Under Slack's section limitEach Block Kit section maxes out at 3000 characters. Use 2990 as your soft cap. Truncate with an ellipsis rather than failing the whole message.6. Under Slack's header limitHeaders max out at 150 characters. Truncate hard. Users will not scroll to read an overflowing header.7. Numeric claims are verifiableExtract every dollar, percentage, and metric from the response. Cross-reference against the data context that was passed to the AI. If the AI claims "ROAS is 4.2x" and no context mentions that number (within a 5% tolerance), flag as unverified. Log the confidence score. Below 60% verified = warning attached.8. No promises of follow-up messagesReject phrases like "I'll investigate further", "Let me look into that", "I'll report back shortly". Every agent message is standalone. Follow-ups never come.9. No em dashesHouse style: em dashes are banned in written output. Replace with commas, periods, or colons.10. No fabricated timestampsIf the AI generated a time-of-day or a date without source data to back it up, flag it. "Yesterday at 3 PM" is only valid if the context has a matching event timestamp.11. Soul metadata consistencyThe response header should match the agent's slack_display. The emoji should match the soul's emoji field. If the AI invented a different name or emoji, correct it before posting.12. Action buttons have valid action IDsEvery actionId in the actions array must match a registered handler prefix (proposal-, deliberation-, video-edit-, etc.). Orphan buttons that nothing handles lead to silent failures when clicked.Order of operationsRun in this order. Fast checks first, expensive checks last.- Character limits (6, 5) — O(1) - Header/emoji consistency (11) — O(1) - PII and key scan (1, 2) — regex - Client and financial scan (3, 4) — regex + cache lookup - Action ID validation (12) — registry lookup - Follow-up promise scan (8) — regex - Em dash scan (9) — string check - Numeric claim validation (7) — extraction + context match (most expensive) - Timestamp scan (10) — regex + context matchFailure modes- Hard fail: PII leak, API key leak, invalid action ID. Refuse to post. Log security event. - Strip and continue: Other-client data, internal financials. Remove the offending section. Post the rest. - Annotate: Unverified numeric claims, low confidence. Add [unverified] in internal logs, optionally append a confidence footer in internal channels. - Truncate: Over-limit characters. Cut with ellipsis. - Rewrite: Em dashes, banned phrases. Auto-replace before posting.Metrics to track- Validator rejection rate by check type (which checks fire most). - Average confidence score per agent per day. - Strips per channel per week (spikes mean an agent is leaking regularly and needs a prompt fix). - PII / API key incidents (should be zero; any non-zero triggers a postmortem).When to update this listAdd a new check whenever a production incident slips through. Remove a check only after a quarter of zero triggers. This list should grow with your system's failure history.Response Filter ExamplesBefore and after examples showing how the response filter cleans agent output.The filter runs on every outbound message in strict-enforcement channels. It removes other-client data, internal commentary, credentials, and banned style. It never rewrites meaning; it strips.Example 1: Other-client data leakChannel: #northwind-skincare (strict, client_id=northwind-skincare)Raw agent response (before filter):Northwind Skincare's ROAS this week is 3.8x, up from 3.2x last week. For context, Meridian Outdoors is running at 4.1x and Summit Roasters is at 2.7x. Your primary lever is the broad audience split.Filter actions:- Detected Meridian Outdoors and Summit Roasters in the cached client name list. - These are not the scoped client for this channel. - Strip the second sentence. - Log a security event with the stripped text.Posted response:Northwind Skincare's ROAS this week is 3.8x, up from 3.2x last week. Your primary lever is the broad audience split.Example 2: Internal financial commentaryChannel: #northwind-skincare (strict)Raw:ROAS came in at 4.2x this week. Our markup on this account is running healthy given the conversion volume. Recommendation: scale the top 3 ad sets by 20%.Filter actions:- Matched pattern our markup. - Strip the sentence containing it.Posted:ROAS came in at 4.2x this week. Recommendation: scale the top 3 ad sets by 20%.Example 3: API key in responseChannel: anyRaw:I pulled the data using token xoxb-1234567890-abcdef.... The campaign had 1,204 purchases.Filter actions:- Detected xoxb- prefix. - Hard fail. Do not post. - Log security event at P0. - Page the security on-call. Rotate the token.Posted: nothing. The user sees no message. An internal ops alert fires instead.Example 4: Em dash replacementChannel: anyRaw:Frequency is up — 4.2 on the hero creative — which matches the CTR decline window.Filter actions:- Replace em dashes with commas and periods.Posted:Frequency is up, 4.2 on the hero creative, which matches the CTR decline window.Example 5: Follow-up promise strippedChannel: anyRaw:The CAC for new customers climbed to $42. I'll run a deeper diagnostic and follow up shortly.Filter actions:- Matched the follow-up promise pattern. - Strip the trailing sentence.Posted:The CAC for new customers climbed to $42.Example 6: Unverified numeric claimChannel: #northwind-skincare (strict)Raw (AI response):ROAS is 3.8x on Meta and 2.6x on Google Ads. CAC is $38 blended.Context provided to AI contained: Meta ROAS = 3.8x, Google ROAS = 2.6x. CAC was not in context.Filter actions:- Extract three metrics: 3.8, 2.6, 38. - Cross-reference: 3.8 verified, 2.6 verified, 38 unverified. - Confidence score: 2/3 = 66%. Below 70%. - Strip the unverified metric sentence OR annotate internally depending on config.Posted (strip mode):ROAS is 3.8x on Meta and 2.6x on Google Ads.Posted (annotate mode, internal channel only):ROAS is 3.8x on Meta and 2.6x on Google Ads. CAC is $38 blended. (confidence 66%)Example 7: Full strip (all sections flagged)Channel: #northwind-skincare (strict)Raw:Meridian Outdoors showed a similar pattern. Our margin on Northwind Skincare is comfortable. Based on both, I recommend pausing the bottom three ad sets.Filter actions:- Sentence 1 mentions Meridian Outdoors (foreign client). Strip. - Sentence 2 mentions margin (internal financial). Strip. - Sentence 3 is the only survivor.Posted:Based on both, I recommend pausing the bottom three ad sets.Note the response now reads oddly ("based on both" with no prior context). This is an accepted tradeoff. Leaks are worse than awkward phrasing. In a follow-up, the agent should be retrained to avoid the leak at generation time, not just strip at post time.Example 8: Full message suppressedChannel: #northwind-skincare (strict)Raw:Meridian Outdoors's CAC is $42 with our 18% margin. Their creative mix is dominated by UGC and internally we think that is why.Filter actions:- Every sentence contains either foreign client data or internal commentary. - All sections stripped. - Response is empty after filtering. - Suppress entirely. Log security event. Do not post.Posted: nothing. A separate ops alert fires.Principles- Strip, do not rewrite. Never try to paraphrase around leaked data. - Log every action. The security team should be able to trace every strip. - Fail safe. Empty response is better than a leaked response. - Fix upstream. When a filter fires repeatedly for the same agent, the prompt needs adjustment. The filter is the last line, not the first.
