# Request acceptance brief

Read the complete request and constraints. Create request-brief.md with: outcome, audience, exact deliverables and file formats, quantities, deadline, explicit exclusions, available evidence and acceptance criteria. Assign stable requirement IDs R1, R2, etc. Keep original wording beside each interpretation. Do not infer personal facts, budgets, dates, access or authorization. Record missing inputs and ask only questions whose answers change a deliverable or a required execution dependency, at most three at once. Use placeholders for optional details. Preserve negative constraints and every requested language, count and platform. For an unsupported domain state that this is a general method and identify the specialist review it still needs. Save the requirements as the plan for the next step. No external actions are authorized by this brief.

## Before you start
Use the material below to do this job. If facts or tool access are missing, explain what you can finish and what must wait.

**What you need** (use your own material or the linked skill):
- **A buyer brief**, made by the [Buyer brief writer](https://useaiblocks.com/skills/buyer-brief-writer): who it's for, how much they already know, and what will move them.

**Recommended steps before this one** (optional; do each once, then reuse what it makes):
1. **A buyer brief** with the [Buyer brief writer](https://useaiblocks.com/skills/buyer-brief-writer). Bring customer words. It uses your brand brain.
2. This one.

How to start:
1. **Look first.** Use what they've already attached, pasted or put in their about-me note. In a coding assistant with file access, look in the project too for these by name.
2. **Check what's missing.** Look for a buyer brief. They can attach files, paste the details, or share a file path your assistant can read. Offer the linked skills above when they help prepare that material. Ask only for missing facts that change the result. If they ask you to start with what they have, complete the parts you can and mark the gaps.
3. **Do the job.** Follow the method with the facts and tools you have. Mark each gap with `MISSING:` where it belongs and never invent a fact to fill it. Keep the answer tight: say each point once and merge steps that give the same thing. In CHECKS MISSED, list checks that failed or could not run. If every required check ran and passed, write “none”.
