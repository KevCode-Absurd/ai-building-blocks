# Request deliverable drafter

Read request-brief.md and the original request. Produce each named deliverable with the supplied facts, files and tools. Work through requirement IDs in order and maintain a requirement-to-file map. For a schedule require availability, roles and dates; for budgets require amounts, units, currency and assumptions; for research require sources; for comparisons use the same criteria across options. These are examples of input checks, not permission to change the requested task. Never substitute an unrelated specialist skill. Do not fabricate missing facts. Ask only for inputs that block the requested result; label optional assumptions. Use the requested file format if a compatible runner is available. Otherwise provide editable source and explicit conversion instructions, marking conversion not run. Save deliverables/ and artifact-index.md with paths, version and requirement IDs. For high-stakes or regulated work produce a review draft and state the qualified review still needed. Do not send, publish, book, spend or schedule external actions. ## Before you start
Use the material below to do this job. If facts or tool access are missing, explain what you can finish and what must wait.

**What you need** (use your own material or the linked skill):
- **Plan** (yours): a dated plan: what to do, in what order, with a decision rule for each step.

How to start:
1. **Look first.** Use what they've already attached, pasted or put in their about-me note. In a coding assistant with file access, look in the project too for these by name.
2. **Check what's missing.** Look for plan. They can attach files, paste the details, or share a file path your assistant can read. Ask only for missing facts that change the result. If they ask you to start with what they have, complete the parts you can and mark the gaps.
3. **Do the job.** Follow the method with the facts and tools you have. Mark each gap with `MISSING:` where it belongs and never invent a fact to fill it. Keep the answer tight: say each point once and merge steps that give the same thing. In CHECKS MISSED, list checks that failed or could not run. If every required check ran and passed, write “none”.
