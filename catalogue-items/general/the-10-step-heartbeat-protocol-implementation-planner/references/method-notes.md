Budget checks, wakeups, inbox processing, issue checkout, responsibility execution, proposal recovery, and goal drift detection.What this isThe heartbeat is the core execution loop of an agent. It runs on a schedule or event trigger and ensures the agent consistently picks, executes, and tracks work without conflicts or duplication.Pre-flight safeguards (before anything runs)Before the agent does any work, four checks can stop execution entirely:- Feature gate: ensures the agent is enabled - Budget: prevents execution if the agent has no remaining spend - Concurrency: guarantees only one heartbeat runs per agent at a time - Timeout: caps total execution time (typically 10 minutes)If any of these fail, the heartbeat is skipped safely.Core flow (10 steps)- IdentityLoads the agent’s configuration, responsibilities, and permissions. If the agent is not registered, execution stops. - Pending approvalsChecks for items waiting on human approval. These are used for prioritization but not executed. - Approved proposalsFetches approved work that hasn’t been executed yet. - Claim wakeupsAtomically claims any pending triggers to avoid duplicate processing. - Load inboxPulls all active issues assigned to the agent, ordered by priority and status. - Pick workSelects exactly one task using a priority cascade:- Resume in-progress work first - Then execute approved proposals - Then review items - Then new tasks - Then proactive responsibilities6e. RoutinesRuns scheduled tasks like audits or summaries.6f. Goal driftChecks performance metrics against targets. If drift is detected, creates new proposals automatically.- CheckoutLocks the selected issue so no other heartbeat can process it. - ContextLoads all related data (comments, dependencies, history) needed to execute properly. - ExecutePerforms the actual work. This is where agent-specific logic runs. - CheckinUpdates the issue status, logs actions, and releases the lock. Even on failure, the system ensures the issue is not stuck.Finalization (always runs)After execution, the system:- Calculates cost based on AI usage - Stores a full run record (status, summary, metrics) - Updates the agent’s last heartbeat timestampThis step is designed to never fail, ensuring system consistency.System behaviorThe heartbeat can be triggered in two ways:- Scheduled runs (like cron jobs) - Event-based triggers (like approvals or assignments)Both paths go through the same execution pipeline.Reliability designThis system is built to prevent:- Duplicate work (via concurrency + checkout locks) - Lost work (via recovery and persistent state in database) - Infinite loops or stuck jobs (via timeout and status control) - Silent failures (via logging and run records)Common failure patterns- Concurrency conflict: another heartbeat is already running → safely skipped - Missing indexes: slows down proposal queries → requires database optimization - Partial execution: a job is claimed but not finished → next heartbeat recovers - Crash during execution: checkout is cleared in finalization to prevent lock - Invalid state transitions: error is logged and retried in the next run - Slow cost calculation: can be moved async if neededBottom lineThe heartbeat is the control system of your agent architecture.It ensures that:- Work is always progressing - Priorities are respected - State remains consistent - Failures are recoverable
