# Case Competition Deck Anatomy

Detailed reference for structuring an MBB-style case competition deck. Use alongside `SKILL.md`.

## The action title (the single most important habit)

Every slide title is a **complete sentence that states the takeaway** — a claim the slide then proves.

| Label (weak) | Action title (strong) |
|---|---|
| Market Analysis | The premium segment is growing 3× faster than the core and is underserved |
| Financials | Repricing lifts operating margin by 4.2 pts and pays back in 2.3 years |
| Competition | No incumbent covers the SMB tier, leaving a $180M opening |
| Recommendation | Enter the SMB tier via a channel partnership within 12 months |

**The titles test:** read only the titles, top to bottom. They must form a coherent argument that lands the recommendation. If they read as topics, rewrite them as claims.

Patterns:
- Lead with the insight, not the activity.
- Put the number in the title when the number *is* the point.
- Use active verbs; be specific to *this* company.
- One claim per title — if there are two, split the slide.

## The Pyramid Principle (Minto)

```
            RECOMMENDATION  (governing thought — the answer)
           /       |        \
     Reason 1   Reason 2   Reason 3   (MECE key line — 2–3 reasons)
      / | \      / | \       / | \
   evidence   evidence    evidence    (data, analysis, charts)
```

- Lead with the answer; support with 2–3 mutually exclusive, collectively exhaustive reasons; back each with grouped evidence.
- Every slide ladders up to the recommendation. Cut anything that doesn't.
- The deck must make sense even if a judge skips around.

## Slide types and what goes on each

### 1. Title
Case name, team name, date. Clean and minimal. No content.

### 2. Executive summary (the answer — most important slide)
- **Recommendation** stated in one bold sentence.
- **2–3 supporting reasons** (these become the section headers).
- **Quantified impact** (the headline number: revenue, margin, ROI).
- Optionally a one-line "the ask" or next step.
- A judge who reads only this slide gets the full answer.

### 3. Context / problem
- The situation in 2–3 facts.
- The **decision to be made**, stated explicitly.
- The success metric / what "good" looks like.
- Keep it short — judges know the case.

### 4. Approach (optional)
- The framework used and the key questions.
- Show the issue tree if it clarifies the logic.
- One slide max; don't teach the framework, use it.

### 5. Analysis sections (one per supporting reason)
- Action title = the reason as a claim.
- One chart or visual that proves it.
- Minimal text; footnote sources and assumptions.
- Chart type fits the data (use the `dataviz` skill).

### 6. Financials
- Market sizing (top-down and bottom-up).
- Revenue/margin bridge or profit walk.
- ROI / NPV / payback with the discount-rate rationale.
- Sensitivity on the 1–2 drivers that matter.
- Every number sourced; assumptions labeled.

### 7. Recommendation & roadmap
- Restate the recommendation (same words as the exec summary).
- Implementation phases with a timeline.
- Owners, milestones, and the first move.

### 8. Risks & mitigations
- The 3 biggest risks and how you'd mitigate each.
- Shows business judgment and second-order thinking.

### 9. Appendix
- A clear divider slide ("Appendix").
- One backup slide per anticipated tough question.
- Detailed models, benchmarks, sensitivities, rejected options, assumption catalog.
- Index/label them for retrieval in under 5 seconds during Q&A.

## Deck flow variations by case type

- **Profitability decline:** context → profit tree → revenue driver → cost driver → recommendation → financials → risks.
- **Market entry:** context → market attractiveness → competitive gap → capability fit → entry mode → financials → roadmap → risks.
- **Growth strategy:** context → where to play (Ansoff) → how to win → economics → roadmap → risks.
- **M&A / investment:** context → strategic rationale → synergies → valuation → integration risk → recommendation.
- **Pricing:** context → willingness-to-pay → competitive benchmark → proposed pricing → margin impact → risks.

Keep the main narrative to the reasons that carry the recommendation; everything else goes to the appendix.

## Design guidance (executive, not flashy)

- **Palette:** one deep primary (navy / forest / slate) + one accent for emphasis; grays for structure. Avoid AI-slop purple-on-white gradients.
- **Type:** one clean, credible family; large action titles, restrained body. Numbers prominent.
- **Layout:** consistent margins, a persistent action-title band, a footer with source + page number.
- **Charts:** lead with them; label directly; highlight the one data point that matters.
- **Restraint:** whitespace and clarity read as confidence. Judges score substance — don't let decoration compete with the argument.
