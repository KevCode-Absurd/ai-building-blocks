## Purpose
Queries recent orders and surfaces those with high or medium fraud risk scores, including the specific risk indicators flagged by Shopify (billing/shipping address mismatch, risky email domain, high-risk IP, etc.). Produces a prioritized review queue for manual fraud assessment. Read-only — no mutations.

## Prerequisites
- Authenticated Shopify CLI session: `shopify store auth --store <domain> --scopes read_orders`
- API scopes: `read_orders`

## Parameters

| Parameter | Type | Required | Default | Description |
|-----------|------|----------|---------|-------------|
| store | string | yes | — | Store domain (e.g., mystore.myshopify.com) |
| risk_level | string | no | high | Minimum risk level to include: `high`, `medium`, or `all` |
| days_back | integer | no | 7 | Lookback window for orders to review |
| min_order_value | float | no | 0 | Only include orders above this value (USD) |
| format | string | no | human | Output format: `human` or `json` |

## Safety

> ℹ️ Read-only skill — no mutations are executed. Safe to run at any time. Risk scores are generated by Shopify's fraud analysis and are advisory only — they do not block orders automatically unless you configure Shopify's fraud filters.

## Workflow Steps

1. **Build the search.** Use `created_at:>='<NOW - days_back days>'` as the base query. Filter on risk level in the query with `risk_level:high` (for `high`), or `risk_level:high OR risk_level:medium` (for `medium`). For `all`, leave the risk filter out and keep every level. If the store rejects the `risk_level` filter, fetch the orders without it and keep the ones with a matching `riskLevel` in code. Say which approach you used.
2. **Fetch the orders.** Run the `orders` query below with `first: 250`. Repeat with the `endCursor` as `after` until `hasNextPage` is false.
3. **Handle missing scores.** If `riskLevel` is null (the order is too new for analysis), leave it out and count how many you left out.
4. **Apply the minimum order value.** Drop orders whose `totalPriceSet.shopMoney.amount` is below `min_order_value`. The default is 0, so nothing is dropped unless the user sets a number.
5. **Sort.** Put high risk first, then medium, then low. Within a level, put the larger order value first.
6. **Write the file.** Save `risk_report_<YYYY-MM-DD>.csv` with the columns listed under Output Format. Join the `riskFacts` messages into the `risk_indicators` column.
7. **Report.** Print the summary in the Session Tracking format, and say how many orders were left out in step 3.

The CSV holds customer names and email addresses. Tell the user to keep it private and not paste it anywhere public.

## GraphQL Operations

```graphql
# orders:query — validated against api_version 2025-01
query OrderRiskReport($query: String!, $after: String) {
  orders(first: 250, after: $after, query: $query) {
    edges {
      node {
        id
        name
        createdAt
        displayFinancialStatus
        displayFulfillmentStatus
        totalPriceSet {
          shopMoney {
            amount
            currencyCode
          }
        }
        riskLevel
        riskFacts {
          message
          sentiment
        }
        customer {
          id
          displayName
          defaultEmailAddress {
            emailAddress
          }
          numberOfOrders
        }
        shippingAddress {
          countryCode
          city
        }
        billingAddress {
          countryCode
          city
        }
      }
    }
    pageInfo {
      hasNextPage
      endCursor
    }
  }
}
```

## Output Format
CSV file `risk_report_<YYYY-MM-DD>.csv` with columns:
`order_name`, `order_id`, `created_at`, `risk_level`, `total_price`, `currency`, `customer_name`, `customer_email`, `risk_indicators`, `financial_status`, `fulfillment_status`

## Error Handling
| Error | Cause | Recovery |
|-------|-------|----------|
| `THROTTLED` | API rate limit exceeded | Wait 2 seconds, retry up to 3 times |
| No high-risk orders | Clean period | Exit with summary: 0 flagged orders |
| `riskLevel` null | Order too new for analysis | Exclude from report, note count |

## Best Practices
- Do not auto-cancel high-risk orders — put them on a manual hold in the Shopify admin first, then review before cancelling.
- An order from a repeat customer (`numberOfOrders > 3`) with a high risk score is often a false positive (a rule of thumb to test on your own orders, not a fact) — apply judgment before acting.
- `min_order_value` helps focus review effort on high-value fraud risk; $50 is a starting point to test on your own orders, not a standard.
- Run daily as part of a morning ops routine, especially during high-volume sale periods when fraud attempts increase.
