# Personal minds and task councils

Create profiles in **Compose → My minds** or **Minds → My minds**. Give a mind a name and purpose, describe its writing voice and working principles, list things to avoid, and paste writing samples. Two or three representative examples with specific style notes are a useful starting point. Run a small task with the downloaded profile, compare the result with those examples, then edit the profile.

Signed-in profiles are saved privately to the current account and load on other devices after sign-in. The library refreshes when the page regains focus, and Refresh account minds checks for changes explicitly. Signed-out profiles stay in this browser. Copy browser minds to account lets the user select existing profiles to copy; it never uploads them automatically and retains browser backups. Conflicting identifiers preserve both profiles. Export a mind JSON file as a portable backup. Markdown and text uploads become samples to review and describe before saving; exported mind JSON preserves the full structured profile. PDF and Word files are not accepted. A standalone Markdown download gives an AI assistant the profile instructions.

Open a workflow task to find **Minds for this task**. Select one mind or up to six for a council. Two recommendations use source attribution first, then matching subject areas; a general reasoning perspective is used if no subject match is available. Personal minds are available as separate choices. The first selected mind sets the final writing voice.

The workflow ZIP includes every assigned mind's instructions under `skills/`, reimportable personal profiles under `minds/`, and a `TASK-COUNCIL.md` protocol when needed. `HANDOFF.md` and `workflow.json` name each task's council and overrides; original task skill files remain unchanged. Council members give separate initial views, challenge conflicting assumptions once, and produce one checked deliverable with unresolved dissent. The pack prepares instructions; council execution happens in the user's AI runner. A single runner can simulate the discussion; separate agents require runner support and the user's authorization.

Account profiles can be selected across workflows and devices. Assignments and embedded profile snapshots survive local workflow saves, editable workflow JSON, shared workflow links and task reordering. Legacy single-mind workflows continue to open. Only assigned personal profiles are included in a workflow pack or link; unrelated profiles stay in their library. Signing out clears the in-memory account library. Browser workflow drafts and exports remain separate, portable copies. Sharing or downloading a workflow exposes its assigned profiles to anyone who receives it. Existing imported workflows keep their embedded profile snapshot.

The profile limits are twelve minds, with bounded fields and eight thousand characters of samples per profile. Import validation checks identifiers, lengths, types and collisions. Uploaded text is never installed or rendered as HTML. Writing examples are quoted as style references and do not supply factual evidence or authorize actions. Browser storage can be cleared; keep exported backups.

Validation: `site/test/custom-minds.test.mjs` and `site/e2e/custom-minds.spec.ts` cover profile validation, imports, excluded unrelated samples, complete downloads, a fresh browser importing an exported workflow, mobile selection and task reordering. Compose fixture tests cover the existing workflow packs and authentication UI; the independent voice tests cover Whisper.

## Account storage and concurrency

The authenticated /api/minds GET and PUT endpoints derive ownership exclusively from the verified Clerk session. Caller-supplied owner IDs are rejected on writes and never influence reads. The COMPOSER D1 binding stores one bounded library per user; apply migrations/0006_account_minds.sql before deploying. Existing data is preserved by this additive migration. Every write compares the library revision in one SQL statement, so concurrent devices cannot silently overwrite each other or bypass the twelve-profile limit. Stale edits require refreshing and reviewing the latest profile; Save my version instead is an explicit replacement choice. Network failures retain the edit form and offer draft export. Removal updates the account library and offers undo; old workflow snapshots are unchanged.

Tests in account-minds.test.mjs cover real RSA-signed authentication, cross-account isolation, strict payload validation, Unicode migration, concurrent SQL writes, stale requests, explicit migration and failed saves. account-minds.spec.ts uses two independent browser contexts with a simulated authenticated API to verify cross-device reuse, actual workflow downloads, account switching, conflict review and mobile layouts. Actual production API/account checks are reported separately; fixture tests do not claim to verify Clerk's production service.
