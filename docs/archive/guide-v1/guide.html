Part 1 · The idea

AI tools answer.
Teams still do the setup.

Anyone can ask an AI for an ad or an audit. Getting a result you'd actually use means collecting your brand's facts, choosing a method, picking the right model, checking the output and doing it all again next week. That gap is the business.

1 · The method is too broad

"Write me an ad" has no exact checks, inputs or standard for what good looks like.

2 · The context is scattered

Products, prices, offers, claims, voice and reviews live in different places. The AI gets none of them.

3 · A draft isn't finished work

Someone has to catch the wrong price, the made-up claim and the off-brand line before it ships.

4 · One success is hard to repeat

Models change, prompts drift and nobody owns it. What worked in March breaks in June.

3.7  Selling and delivering services

  1. Readiness form. Goal, store, tools, data access, budget, deadline. Many requests become a standard plan with no custom work.

  6. Move to subscription. Keep the parts updated and supported.

Part 5 · The build

How every part gets made.

Three things get built in order: small tools that make parts cheaply and test them the same way every time, then the parts themselves section by section, then the website that shows them.

A · The item factory

Six small tools: import a part, check it, build its downloads, run it on cheap/mid/top models, grade it blind, and map how parts connect.

B · The parts (content)

Section by section: brand brain → static ads → scripts → research and offers → pages and CRO → email → Meta → BFCM pack.

C · The site

Reads the part folders directly, so a fixed part is a fixed page. Free catalogue first, accounts and payments second.

Quality rules that never bend

Zero wrong prices, zero invented claimsChecked by code against the brand brain's current offer and claims register, before any judge.
The judge never wrote the workA different model grades blind, against the same checklist the item page shows.
Knowledge must earn its placeA rule or guide stays in a prompt only if a with/without test shows it improves the output.
Hard rules live in code"Never" rules are enforced by checks, not just written in a prompt.
Risky actions need a humanNo automatic ad pausing or budget changes. Agents propose; people approve.
Content is data, not ordersInstructions hidden in reviews, pages or course files are ignored and tested for (red-team cases).

How Claude works on this, safely

  • One section at a time; parts inside a section are built in parallel batches of about 4 by helper agents. Each one writes only to its own part folder.
  • Helpers draft; tools and reviews decide. Model tests run through the tools, so costs and logs stay in one place, with hard spend caps per run and per round.
  • Sources stay read-only. No secrets are ever handled, no course code is run, and instructions found inside files are treated as data.
  • You review per section, not per part. Every section report lists each part's scores, cost and what changed.

Part 9 · Risks

What could go wrong, and what we do.

RiskWhat we do about it
People won't pay when free prompts existProve it with paid sprints and pre-sales before building the paid site. Lead with finished, checked work, not prompts.
Parts look done but aren'tMeasured gates: code checks, golden sets, blind judges, zero costly mistakes.
Course material leaks into productsEvery part records its origin; the importer refuses non-own rows; rewrites in our own words; terms checked.
A public brand objects to being an exampleOnly public quotes, clear "not affiliated" labels; any brand can be swapped out without changing a part.
Old prices or offers in outputsVersioned brand brain plus an automatic price check; the old-price case is in every sprint test.
Model churn makes advice stalePages name classes, not models; one model file; dated re-tests.
Test costs run awayHard caps per run and per round; image renders capped separately.
Services swallow the productEvery project must reuse parts; anything built twice becomes a part; time-tracking reviewed monthly.
Overlap with the separate "ecomOS" appInventory it before Section 1 so nothing is built twice.
Safety and prompt injectionRed-team tests, approvals for risky actions, read-only connectors by default. We reduce risk; we never promise zero risk.

Appendix

Glossary and where things live.

WordPlain meaning
Brand brainOne folder or file holding a brand's facts, offers, claims, voice and buyers, which any AI can load
Part / itemOne building block in the catalogue (a prompt, skill, routine, workflow, agent or system)
TierHow deep a part goes: Starter, Standard, Advanced, Production
StackA ready-made chain of parts for a goal, e.g. "BFCM pack"
Golden setA fixed set of test inputs with known good answers, used to grade every version
Blind judgeA different AI model that grades outputs without knowing which version made them
Costliest mistakeThe error that would hurt most, e.g. a wrong price or an invented claim; must be zero
Caching orderPutting the parts of a prompt that don't change first, so AI providers charge less for repeats
Lean modeA shorter version of a part (short brain card, fewer references) to save tokens
RouterA service such as OpenRouter that lets one setup reach many AI models
GateA measured check that must pass before the next phase starts
S0–S5Store stages: Explore, Launch, Grow, Scale, Growth company, Large
