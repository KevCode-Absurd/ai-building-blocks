PRODUCT REQUIREMENTS

As of 17 October 2026 | Version 2026-10-17-current-five-stream-plan

THE COMPLETE CUSTOMER LADDER

Prompt: one task, explicit inputs, approved company context and an example result.

Skill: reusable instructions with optional scripts, references, input checks, failure cases and output tests. It can work alone.

Workflow: an ordered set of selected skills, tool calls, calculations and human checkpoints. Its configuration records which modules are enabled and the evidence each one needs.

Routine: the same workflow with an approved schedule or trigger, a durable runner, failure alerts and an owner. A downloadable instruction file alone is not a scheduler.

Agent or worker: a bounded responsibility with approved skills, tools, saved state, budgets and escalation rules. Multiple roles may cooperate only where evaluation shows a benefit.

Application: a customer interface plus database, access controls, agents or workflows, logs, deployment and maintenance. A full application is a separate engineering scope, not automatically included in a library subscription.

MINIMUM PRODUCT EXPERIENCE

Discover by exact task, function, industry, output and host. A task page shows a complete labelled sample, required inputs, compatible tools, likely review effort, limits and last evaluation date. Industry-specific examples should be easy to find without forcing every customer through the same template.

Preview the output, choose modules, select a data route and confirm the payer. For example, a user can request only Meta data, only three analyses, a chosen database destination and an audit-only report. The configurator validates prerequisites and creates a versioned configuration; it should not blindly generate arbitrary executable code.

Provide a manual download pack as well as supported integrations. The pack contains the method, input template, selected permitted references, output contract and setup instructions. Preserve a useful fallback when an account cannot use a connector or a native host tool is unavailable.

Save private company facts, accepted outputs, rejected references and settings under the correct organisation and brand. Shared methods and public references remain separate from private customer evidence. Agencies need client boundaries, member roles and approval ownership.

Explain the next useful step after a result: repair missing data, research a creative gap, prepare a new brief, create an asset, schedule a repeat review or stop. A suggested next task does not itself authorize a paid run or write.

PROPOSED FIRST RELEASES

First prove a brand-aware audit and a reference-backed static-ad task. Candidate audit modules are data readiness, basic efficiency totals, creative diversity, new-versus-established spend mix and optional fatigue analysis. Every module needs an exact definition and an unavailable state when evidence is missing.

Candidate launch pages are a brand or landing-page audit, a scoped Meta ad audit and a BFCM static-ad brief or creation workflow. Creative-fatigue review is a separate module with daily-history requirements. These are proposed launch choices, not completed products or a commitment to launch every module together.

Acceptance for a first release means an approved test brand, at least one held-out brand, deliberate failure cases, usable final artifacts and measured human effort. Thresholds and sample sizes must be set before judging the candidate. A small demo or model self-score cannot establish production readiness.

LIBRARY AND REFERENCE BOARDS

Use boards for static ads, videos, editorials and other relevant outputs. Tag assets by industry, product type, audience, message, offer, format, visual treatment, date and source. Store ownership or licence evidence, permitted uses, expiry and any restrictions on downloads, model use or redistribution.

Customers can browse and pick references or ask the platform to rank relevant options against their approved brand profile and task. Return reference IDs, roles and selection rationale. A layout reference is not authority to copy a competitor's claim, logo or protected product image.

The selection packet must make actual permitted media available to the execution route. A board URL or preview thumbnail alone is not proof that a model inspected the asset. Support manual attachment when native media delivery fails.

Foreplay and similar libraries are potential source tools, not assumed rights to mirror or resell every asset. Verify terms, export/API access and rights for each intended route. Keep private client boards private. A no-match result is better than an irrelevant or unauthorised reference.

WHY CHOOSE US AND KEEP PAYING

Differentiate on a narrow task, demonstrated output, company-specific configuration, tested methods and accountable implementation. Measure whether customers actually finish useful work faster with less correction than with their existing setup.

Paid renewal supplies maintained releases, fresh permitted references, compatibility updates, saved team standards and defined support. Show release notes and evaluation evidence. Keep accepted work pinned to its exact method and reference versions, with a deliberate upgrade path.

Scale by reusing methods, schemas, calculations, connectors, examples and training. Keep standard setup bounded, charge for unique engineering and train delivery partners. Add outside builders only after there is a review process, a licence model, maintainer responsibility, incident handling and evidence of buyer demand.
