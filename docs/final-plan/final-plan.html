What we're building

A free, evergreen library of tested AI building blocks. It isn't only skills. It has simple prompts, skills, routines, workflows, applications, mini tools, and your own agents and bots, plus plain how-to guides for setting each one up yourself. A complete beginner gets something useful on day one, and an expert finds the next level up. It starts with general skills any business can use. On top of that sit industry boards, starting with /ecommerce, where the skills are more focused and more valuable, and people download, comment and get advice, a bit like Reddit communities. Later come boards for job roles such as marketing, finance, operations and product management.

Every listing is tested, explained in plain words and shown with a real before and after, so people who find GitHub overwhelming can still use it. We bring in good skills from around the internet too: we credit and link the original, check it for malware and prompt injection, tighten and improve it, and show what it produces. It stays simple by default: every job is a ladder, and people only see their next step.

Who it's for

Anyone who uses AI for work, in any business. The first deep board is /ecommerce, because that's where our own tested skills are strongest. /saas comes next.

What it costs

Part 1 · The idea

Great AI skills exist. Most people can't use them.

There are thousands of prompts and skills on GitHub and in AI communities. Most people never use them. They can't tell which ones work, whether they're safe, how to install them, or what they'd get. That gap is the business.

1 · Too much, untested

Long lists with no proof of what the output looks like or which model to use.

2 · Not safe to trust

A skill can hide scripts, data grabs or instructions that hijack the AI. Nobody checks.

3 · Made for developers

GitHub, terminals and setup files scare off most business users.

4 · Too general or too narrow

Either it fits nobody well, or it only fits the one business it was written for.

Most people have never connected an AI to anything, and some already run their own apps. So every job in the catalogue is a ladder. It starts with what you do by hand today, and each step automates a little more. You only see the next step, and people who know more can jump ahead. Decided

Part 5 · Skills from the internet

The best of GitHub, made safe and simple.

There are good skills all over the internet, but most people can't judge them, install them or trust them. We find them, check them, credit them, improve them and show exactly what they produce. This is a big job that grows over time. We start once our own skills are ported. Decided

1 FindGitHub, skill hubs, community lists, requests
2 Licencemay we copy and change it?
3 Scanscripts, links, hidden instructions
4 Sandbox runwith trick inputs
5 Tightenremove risky parts, add guardrails
6 Adaptgeneral + board versions
7 Improvetest against the original
8 Publishcredit, link, before/after
9 Watchre-check when the original changes

What the safety check looks for

Code that does things

Scripts or commands that install packages, delete or change files, run on start-up, or are hidden or scrambled.

Data leaving

Web addresses, uploads, or requests for passwords, keys or tokens. A skill should never need your secrets in plain text.

Hijacking the AI

Hidden instructions (prompt injection) such as "ignore your rules", "don't tell the user" or "send this file to…", including in invisible text or comments.

Too much power

Asking for more tool access than the job needs, or acting without a person approving.

Trick inputs

We run it on poisoned pages and files to see whether it follows instructions buried inside them. It must treat content as data, not orders.

Pinned version

We review one exact version. If the original changes, our copy doesn't change until it's checked again.

The scan is done by a tool (scan-skill) and then read by a person. Anything with scripts is only ever run in a sandbox with no secrets and no network access unless the test needs it. We reduce risk; we never promise zero risk. Skills that fail are not listed. If the problem is serious, we tell the original author privately.

The original's licenceWhat we do
Open: MIT, Apache 2.0, BSD, CC BYCopy, adapt and improve it. Keep the original notice, credit the author, link the original and list what we changed.

How Claude works on this, safely

  • One section at a time. Listings inside a section are built in parallel batches of about 4 by helper agents, each writing only to its own folder.
  • Helpers draft; tools and reviews decide. Model tests run through the tools, so costs and logs stay in one place, with hard spend caps.
  • Outside skills are untrusted. They're downloaded into their own empty folder, never run outside a sandbox, and any instructions inside them are treated as data.
  • Sources stay read-only. No secrets are ever handled, and Creative Engine is never edited from here.
  • You review per section, not per listing. Every section report lists each listing's scores, cost and changes.

Prompt injectionHidden text that tries to make an AI ignore its rules or do something the user didn't ask for
Brand brainOne file with a business's facts (what it sells, offers, claims, voice, buyers) that any AI can load
Ladder / step / levelThe path for one job, from by hand (0) to agents (8); each step's level is Beginner, Intermediate, Advanced or Expert
Connector (MCP)A one-time link that lets an AI read a tool such as Meta Ads or Google Sheets for you
Golden setFixed test inputs with known good answers, used to grade every version
Blind judgeA different AI model that grades outputs without knowing which version made them
GateA measured check that must pass before the next phase starts
