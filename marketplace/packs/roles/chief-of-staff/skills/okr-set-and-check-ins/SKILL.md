# OKR set and check-ins

## When to use

- Before a new quarter, to set the team's goals.
- When a team has draft OKRs that read like task lists or have no numbers.
- Every week, for a short check-in on the key results.
- At quarter end, to score honestly and decide what carries over.

Not for performance reviews or pay. If someone wants OKRs linked to bonuses, send that question to the leader and an HR adviser; Google's and Doerr's guidance both keep OKRs apart from evaluations and pay.

## Access needed

- **Level 1 (read):** the year plan, last quarter's goals and results, the scorecard and the data sources.
- **Level 2 (read and draft):** draft the OKR set in a private page, project or sheet; draft the check-in template.
- **Level 3 (read, write and publish):** publish the approved OKRs in the shared goals tool, update key-result values each week from the agreed data source, and post the check-in summary in the agreed channel, within the confirmed limits. Changing a target after it is set needs the owner's and leader's yes.

## What you need

1. The year plan or the leader's few goals for the year.
2. Last quarter's OKRs and how they scored, if any.
3. The numbers you track today and where each one lives.
4. The team, and who could own each result.
5. Any fixed dates in the quarter (launches, hires, seasonal peaks).

## Steps

### 1. Read the plan and the numbers
List the year's goals and last quarter's results. For any measure without a starting value, ask for one. If none exists, the first key result is "measure the baseline by week 3".

### 2. Pick the few objectives
Ask which changes would move the year most this quarter. Draft only a few objectives (Google's guide uses three to five for whole companies; small teams usually need fewer). Each is one plain sentence about a change, not a task list: "Make new customers successful in their first month."

### 3. Write key results
For each objective, write a few key results. Each has a measure that moves, a start value, a target, a date, an owner and a data source: "Customers active in week 4: from 52% to 65% by 31 Mar. Owner: Lena. Source: product dashboard." Remove anything that is a task ("launch onboarding emails") and ask what that task should change.

### 4. Mark each OKR committed or aspirational
Committed: the team expects to fully meet it. Aspirational: a stretch whose path is unclear. They are scored and discussed differently at quarter end.

### 5. Test each key result
- Can someone measure it from data you already have?
- Can the team move it within the quarter?
- Would hitting it mean the objective is met?
- Is it gameable in a way that hurts customers? If so, add a guard measure.

### 6. Add confidence and the main risk
Give each objective a confidence (for example 1 to 10) and its biggest risk. Low confidence on a committed OKR is a planning problem: fix it now.

### 7. Write the "not this quarter" list
Every good idea that was cut goes here with one line on why. This makes cutting easier.

### 8. Set up the weekly check-in
A short slot, the same day each week. Three questions per owner: what moved, what is at risk, what help do you need. One scorecard: each key result's current value, the target and the confidence. A rule the team agrees for asking for help, for example: when an owner's confidence keeps falling, they bring one specific ask to the next check-in.

### 9. Score at quarter end
Score each key result from 0.0 to 1.0 against the target. For aspirational OKRs, Google's guide treats about 0.6 to 0.7 on average as a good outcome; committed OKRs should be met in full. Write what was learned, what carries over, and what stops. Never rewrite the target after the fact to improve the score.

## Checks

- No more objectives than the team can recite.
- Every key result has a start value, target, date, owner and data source.
- No key result is a task.
- Each OKR is marked committed or aspirational.
- Every guessed number is marked [ESTIMATE].
- Nothing links OKRs to pay or ratings.
- The "not this quarter" list exists.

## Output format

1. OKR table: objective, key result, start, target, date, owner, source, committed or aspirational, confidence.
2. Biggest risk per objective.
3. "Not this quarter" list.
4. Weekly check-in agenda and scorecard layout.
5. At quarter end: scores, lessons, carry-over list.

## Example

*Illustrative structure, not a real business: a 9-person online plant shop in Leeds, UK. Copy the shape, never the content: every fact comes from the client's own context. Q1.*

> **Objective 1 (committed): Get every order to the customer on time.**
>
> | Key result | Start | Target | Owner | Source | Confidence |
> |---|---|---|---|---|---|
> | Orders dispatched within 2 working days | 81% | 95% | Sam | Shopify export | 7/10 |
> | "Late delivery" tickets per 100 orders | 6.2 | 3.0 | Ana | Help desk tags | 6/10 |
>
> **Objective 2 (aspirational): Make repeat buying the habit.**
>
> | Key result | Start | Target | Owner | Source | Confidence |
> |---|---|---|---|---|---|
> | Customers who reorder within 90 days | 18% | 25% | Jo | Shopify cohort report | 4/10 |
> | Plant-care subscription sign-ups | 0 | 300 | Jo | Subscription app | 3/10 |
>
> **Not this quarter:** wholesale to cafés (needs a second van); new website theme (no measurable change expected).
> **Biggest risk:** spring peak in March could swamp dispatch. Guard: temp packer booked from 1 March.
