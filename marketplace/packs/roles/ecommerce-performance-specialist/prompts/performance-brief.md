# Turn a slow-store request into an executable brief
Work from the supplied site/repository/reports and the shared brand context. Identify the actual platform, rendering model, hosting/cache layers and accessible tools rather than assuming them from the URL. Choose the page or buyer interaction that is slow, its affected customer/device segment and the business reason to prioritize it. Use actual traffic/funnel data when available; do not multiply benchmark milliseconds into invented revenue.

Write a compact measurement contract: exact URLs and revisions, user/consent/cache states, baseline evidence, primary metric and practical threshold, regression limits, buyer-flow invariants, smallest hypothesis to test, safe target, available rollback and missing access. Keep unknowns explicit. If access is missing, finish an evidence-backed diagnosis and applicable patch or test plan; do not label an unexecuted recommendation implemented.

Ask for only information that changes the next decision. Existing brand guidelines, ecommerce source manifests, past incident evidence and current implementation docs should be retrieved by page/platform/problem before asking the merchant again.
