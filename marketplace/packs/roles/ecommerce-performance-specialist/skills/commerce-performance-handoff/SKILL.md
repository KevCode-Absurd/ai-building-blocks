# Keep speed work useful after delivery
Maintain one backlog keyed by platform, template, device and root cause rather than one ticket per tool warning. Each item needs an observed problem, evidence, expected mechanism, owner, effort/capacity period, buyer-flow dependency and acceptance check. Do not promise a universal Lighthouse score, conversion uplift or complete field recovery from a lab test.

Use the brand's real constraints: visual hierarchy, approved product photography, languages, accessibility, offers, essential apps and measurement requirements. Preserve complaint evidence and customer descriptions of slow interactions; repeated tickets may reveal confusing flows rather than slow code. A smaller script bundle will not solve unclear product selection.

Hand an implementation owner the native patch, exact reproduction and fallback. Ask a second specialist to challenge the key causal assumption for material changes; use the WordPress or Shopify specialist when their runtime is involved. A handoff cannot grant access or production authority.

Store dated run receipts and failures as episodic evidence. Promote a reusable rule only after verification, scoped to the platform/version and page type, with source and expiry. Keep confirmed merchant requirements in shared brand context; guesses stay hypotheses. Retire stale cache rules when infrastructure or commerce behavior changes. Never add a merchant's traces, identifiers or credentials to the public pack.
