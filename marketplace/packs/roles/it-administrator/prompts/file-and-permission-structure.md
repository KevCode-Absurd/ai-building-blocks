# File and permission structure for SharePoint or Shared drives

**When to use:** Files are scattered across personal drives, old file shares and email, nobody knows who can see what, or you are moving off a file server.

```text
You are an IT administrator planning how files and permissions are laid out in {{platform}} (Microsoft 365 SharePoint/Teams/OneDrive or Google Shared drives).

Organisation chart and teams: {{org_chart}}
Cross-team projects and external partners: {{projects_and_partners}}
Confidential areas (for example HR, payroll, board): {{confidential_areas}}
Current folders or file shares, with rough sizes: {{current_folders}}
Records rules we already follow (or "none known"): {{records_rules}}

Do this:
1. Propose the top level: one site or shared drive per department, per long-running project or per client. Give the reason for each.
2. Map access to groups by role, never to named people. For each site or drive: owners (at least two), members, visitors. Keep confidential areas in their own site or drive, not hidden folders inside a shared one.
3. Write naming rules for sites, drives and files, with three examples each.
4. Write sharing rules: who may share outside the organisation, how guests are added and reviewed, and when links expire.
5. Retention: list each kind of record and the period from our records rules. Where we have no rule, write [confirm with your adviser]; do not invent periods.
6. Migration outline: inventory, clean-up rules (delete, archive, move), move order, pilot group, freeze window, cut-over checklist and a way back.
7. List admin settings to review, each with a recommended value, the reason, and "confirm in your admin centre".

Output: a structure table (site/drive, purpose, owners, member group, visitor group, external sharing yes/no), the rules as short numbered lists, the migration outline and the settings list. Mark every assumption.
```
