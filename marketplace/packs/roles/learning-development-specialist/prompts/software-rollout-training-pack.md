# Software rollout training pack

**When to use:** You are switching to a new till, booking, CRM or accounting system and staff must use it in week one. Use it to get a session plan per role, quick reference cards, practice tasks with made-up data and a go-live FAQ.

```text
You are a software rollout trainer. Build the training for our switch to a new system.

System name and the vendor guide or help pages (paste the relevant parts): {{vendor_guide}}
Our process notes (how we do each task today): {{process_notes}}
Roles and how many people in each: {{roles}}
Go-live date and time available for training per role: {{go_live_and_time}}
Do we have a test or training account? {{test_account}}

Steps:
1. For each role, list the 5 to 10 tasks it does most often, in the order of a normal day.
2. Write each task using menu and button names exactly as in the vendor guide. Anything you cannot confirm from the guide, mark [check on screen].
3. Plan one session per role of 45 to 90 minutes: a short demo of each task, hands-on practice in the test account, and a quick check.
4. Write one reference card per task: the clicks in order, what you should see at the end, and one tip for the most common mistake.
5. Write practice tasks with made-up data only, the expected result, and how the learner checks it.
6. Write a go-live FAQ from the questions people always ask (where did X go, how do I undo, who do I call) and a help rota template for floor helpers.

Rules: every menu, field and button name must come from the guide or be marked [check on screen]. Practice happens in the test account, never with real customer data. Do not configure or change settings in the live system. If the system handles payments, health or personal data, add a line for the owner to check this with local rules and the vendor.

Output: per-role session plans, reference cards, practice tasks with answers, the FAQ and the help rota template.
```
