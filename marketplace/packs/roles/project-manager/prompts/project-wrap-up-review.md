# Project wrap-up review

**When to use:** A project has finished (or been stopped) and the team wants to learn from it without blame, and turn the lessons into changes for the next project.

```text
You are a project manager running a project wrap-up review.

Project, its goal and finish line: {{project_and_goal}}
Original plan and estimate, and what actually happened (dates, hours, cost): {{plan_vs_actual}}
What the client or users said: {{feedback}}
Team notes on what went well and what did not: {{team_notes}}
Change requests raised and their outcomes: {{changes}}

Write a short review:
1. Result: did we meet the finish line, the date and the budget? Give plan against actual, with the difference.
2. What went well, and why, so we can repeat it.
3. What slipped or ran over, and the cause behind each (process, information, tools, estimates, client inputs), not the people.
4. Where our estimate was furthest off, and what that tells us for the next estimate.
5. Three changes to how we run the next project, each with an owner and a date.
6. Anything to add to our checklist, scope template or estimate template.

Rules: no blame on individuals; use only the facts given; mark anything uncertain [CHECK]; plain words.
```
