# Site build sheet

A good build sheet turns "I need a website" into a list of small jobs: this section, this block, this text, this image. Anyone can follow it, and nothing is invented.

Access levels for this skill: the plan itself needs only level 1 (read: screenshots, a preview link, the template name). Building the pages as hidden or unpublished pages, duplicate sections or draft CMS items needs level 2. Publishing the pages needs level 3, within the client's limits.

## When to use

- A new site on a builder the client has chosen.
- A template site that grew messy and needs a clear page list.
- Before writing page copy, so the words fit the blocks.

## What you need

- **Access I have**: the level and limits per tool, written down. Until then, level 1.
- The builder, plan and template (or "not chosen yet").
- What the business does, for whom, where, and the one action visitors should take (call, book, buy, enquire).
- The client's text and photos, even rough, and a list of what is missing.
- Brand basics: logo, colours as hex if known, fonts if chosen.
- Who will edit the site after launch.
- Any must-have features: booking, shop, members, blog, forms. Check each against the builder and plan before planning it.

## Steps

1. **Start from what exists.** If the client already has a site, capture it first (skill build-on-existing-site, step 1) and plan inside its global styles, header, footer and section patterns; a new page reuses them. Only a site with nothing to learn from starts blank.
2. **List visitor tasks.** From the brief and the current site, write the five or so things visitors come to do ("see prices", "book a class", "check opening hours"). Ask the client to confirm or reorder them.
3. **Write the page list.** One row per page: its one job, its main action, and the content it must hold. Keep it to what the tasks need; merge thin pages. Name the menu labels in the visitors' words.
4. **Check features against the builder.** For each must-have, note whether the builder and plan do it natively, through an app or integration, or not at all. If not, say so and suggest the simplest route, such as a booking tool linked from a button.
5. **Plan each page top to bottom.** Choose the section order from the visitor's task, where they arrive from and what the category's buyers expect to see (a timetable, a menu, prices, a gallery), not from the template's demo page. For every section: the builder's block or element name (for example a Squarespace Image block in a Fluid Engine section, a Wix Studio stack, a Webflow Collection List, a Framer CMS list), the text or [add], the image with size and focal point, the alt text, and where any button or link goes.
6. **Put the main action in the first screen on a phone.** The headline says what the business does and for whom; the button names the action.
7. **Set image specs.** Give width and aspect ratio per slot. On Squarespace, about 2,500 px wide and under 500 KB suits most images. Keep the top image of each page right-sized and never lazy-loaded.
8. **Write style settings** in the builder's own setting names, taken from the captured site when there is one: heading and body fonts and sizes, colours as hex with what each is for, button style, spacing. Check text and button colours reach 4.5:1 contrast (3:1 for large text).
9. **Plan the footer and the boring pages.** Contact details, opening hours, privacy notice, cookie notice if needed, accessibility contact, and a helpful 404 page.
10. **Order the build.** Global styles first, then header and footer, then pages in order of importance, then forms, then launch checks (skill: site-launch-check).
11. **Build (level 2) and publish (level 3).** At level 2, build hidden or unpublished pages and duplicate any section before changing it. At level 3, show the action list and limits, get a yes, publish, and log each action.

## Checks

- Every page has one job and one main action.
- Every block named exists in the client's builder, version and plan.
- No invented prices, reviews, awards, staff names or results; gaps are [add].
- Every image has a size, focal point and alt text, or is marked decorative.
- Colours pass contrast; buttons are big enough to tap.
- The plan names who edits what after launch.
- Every action stayed within "Access I have" and is logged.

## Output format

1. **Page list**: table of page, job, main action, must-have content.
2. **Feature check**: feature, native / app / not possible, and the route chosen.
3. **Build sheet per page**: table of section, block or element, content, image (size, focal point, alt text), link.
4. **Style settings**: table in the builder's setting names.
5. **Build order** and **open questions** for the client.

## Example of good output (short)

*Illustrative structure, not a real business: a pottery studio with classes, on Squarespace 7.1. Copy the shape, never the content: every fact comes from the client's own context.*

**Page list**

| Page | Job | Main action | Must have |
|---|---|---|---|
| Home | Show what the studio offers and where | Book a class | Next classes, location, photo of the studio |
| Classes | Help people pick a class | Book | Class types, length, level, price [add], dates |
| Private events | Sell group sessions | Enquire | Group size, what's included, enquiry form |
| About | Build trust | Book a class | Teacher bio [add], studio photos |
| Contact | Help people arrive | Get directions | Address, hours, map, phone |

**Build sheet: Home (top part)**

| Section | Block | Content | Image | Link |
|---|---|---|---|---|
| Hero (Fluid Engine) | Image block, Text block, Button block | "Wheel and hand-building classes in [add town]" / "Small groups, all clay and firing included" | 2,500 x 1,400 px, focal point on hands at the wheel; alt "Student shaping a bowl on a pottery wheel" | Button "Book a class" to /classes |
| Upcoming classes | Summary block pointed at the Classes events page | Three next dates | none | Each item to its class |

**Open question:** online booking needs a scheduling tool (a builder add-on or a separate service), which is a paid choice for you; until then each class links to the enquiry form.
