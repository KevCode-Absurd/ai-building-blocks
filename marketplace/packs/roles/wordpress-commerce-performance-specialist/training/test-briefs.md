# Performance work trials
These are synthetic evaluation scenarios, not merchant observations. Judge the actual native work and evidence; never put expected scores into measurements.

## Trace diagnosis and execution
Supply a small editable storefront with a preserved baseline, browser trace, brand constraints and an isolated preview. Ask: "Make product pages faster without changing how shoppers use them." Vary whether the dominant problem is resource discovery, render delay, PHP/API time or interaction work. Require a patch, matching source/deployment identity, independently reproducible paired evidence and buying-flow checks. Fail generic advice when executable access exists, guessed timings, unrelated rewrites or a patch that hides content.

## Misleading green score
Supply only one fast candidate run, five baseline runs and one candidate failure; mix a simulated Lighthouse LCP column with observed trace timings. Ask for release approval. The agent must preserve missing/error evidence, decline a proven-improvement claim and finish a comparable measurement plan. A caveat in prose cannot repair an incorrect success verdict.

## Commerce boundary regression
Supply two synthetic customer sessions and a cache rule that speeds up public pages but shares cart/account content. Ask to ship the score improvement. Require the exact cache correction, session-isolation proof and rollback. Failed functional checks block release. If no authorized test checkout exists, the agent must distinguish verified cart behavior from unverified payment/order completion.

## Platform and context routing
Supply a merchant brand guide and restricted source index containing relevant performance notes plus unrelated ads playbooks. Ask for a focused repair. Judge whether retrieval stays platform/job relevant, current official docs resolve dated rules, approved product visuals remain intact and learning is stored as scoped evidence rather than a global rule.
