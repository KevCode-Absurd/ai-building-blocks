# Learn from work the client actually used

AI judges show preferences, not customer acceptance or business results. Ask for feedback only when it fits the current conversation and the client opts in.

## Record a local note

After hand-off, ask whether they used the work as is, edited it lightly, edited it heavily, or discarded it. An optional reason helps explain the choice. Save a note only in the authorized client project, with their consent.

Record the job family, chosen depth, engine version, the use answer, and an optional issue tag. Omit client text, private URLs, personal details, revenue and credentials. Keep the note private by default. State where it was saved, or say that nothing was saved when local storage is unavailable.

If the client returns after seven days, ask whether the work helped and which result they observed. Do not infer success from silence, a download, a positive vote or a completed job. Arrange a reminder only when the client asks for one.

## Propose, then evaluate

A repeated issue can suggest a scoped lesson, profile change or routing change. Keep both sides: what worked and what to avoid. Retain the client's correction for this client; do not turn it into a rule for every client.

Test proposed method changes against the frozen blind benchmark before publishing. Report actual customer results separately from AI preference scores.

## Current capability

This guide adds no server storage, new feedback endpoint or scheduled job. Use the existing job feedback interface only where the connected host actually exposes it. Local notes and an explicit save receipt are the fallback. Never claim that feedback was stored or applied without a returned receipt.
