# Load test at 3x the library (2026-10-20)

## What we did

We made a fake library of 3,435 blocks (the real 1,135 plus 2,300 made-up skills, most of them "imported" with scripts, references, a LICENSE and a PNG). We built the site from it and used it on a phone-sized screen (375 by 812). Then we rebuilt the real data.

The fake library comes from `tools/make-fake-catalogue.mjs`. The build reads it when you set `CATALOGUE_ROOT`.

## Size of blocks.json (loaded by every page)

| | Before | After |
|---|---|---|
| Raw | 1,136,125 bytes | 773,870 bytes |
| Gzip | 193,351 bytes | 172,217 bytes |
| At 3x (after) | not measured | 1,829,430 raw, 331,611 gzip |

What we cut: a block's file list, word count, added date and test details now live elsewhere (the page file, or a `_files.json` that is only fetched on download). Empty lists and default values are left out and put back when the site loads. Ports and workflow steps use short forms. A headline that equals the name is left out.

Most of what is left is the summary text, which cards and search need. The next big saving would be loading the minds list only on /minds.

## Speed at 3x

| Moment | Result |
|---|---|
| First load of the home page | data fetched in about 25 ms locally, one long task of about 220 ms before the fixes, none in the last run |
| Typing in the library search | about 100 to 150 ms of blocked time per key before; about 50 to 90 ms per key after (0 on a quiet machine) |
| Opening a function or a tab | no long tasks, under 70 ms |
| A block page | no long tasks, page file arrives in about 200 ms |
| Builder, "All" blocks tab | before: 3,300 rows drawn, about 18,500 page elements, 185 ms. After: 60 rows at a time, about 2,300 elements, under 15 ms |
| Builder search and goal box | no long tasks after the fix |

The library list already shows 12 cards at a time, so its page stayed small.

## What we fixed

- The Builder palette drew every block. It now draws 60 and has a "Show more" button. Its search also waits a beat behind typing.
- `taskOf`, `functionsOf` and `areasOf` were recalculated for every block on every key. They are now looked up from a table.
- `neighbours()` scanned every block each call. It now uses an index by port type.
- The goal planner compared words in a slow way. It is now a plain loop.
- Downloads: a skill's extra files are fetched as raw bytes, so images and other binaries come out of the zip unchanged (checked with the PNG).

## What is left

- App.tsx: each key still counts about 50 filters over all blocks, which costs 50 to 90 ms at 3x. Fix: work out each block's task, kind, maker and areas once and count in one pass. Sorting with `localeCompare` could use one `Intl.Collator`.
- The index build takes about 55 seconds at 3x (25 s now), mostly the per-block "what comes before" plan. Worth caching if the library grows again.
- blocks.json at 3x is 1.8 MB raw. Fine on gzip (330 KB), but splitting the minds list out would help.
- Playwright runs can time out when several agents use the machine at once. Failures seen were load, and the same tests passed alone.
