# UI and UX audit, 2026-10-21

Goal from Kevin: make the site fun to use and impeccable. This report lists what gets in the way today and what to change, in priority order. Screenshots are in `reports/ux-audit-shots/` (prefix `d-` is desktop at 1440×900, `m-` is a Pixel 7 phone, both dark theme unless the name says light).

## The short version

The site has a strong, distinctive look: the monochrome palette, pixel icons, hard shadows, dither strips, typing effects and the ladder page all feel like one product. The 22 calculators, the minds wall and the builder's empty state are already the best parts. What stops it being impeccable is not the look, it is five things:

1. **Every deep link lands on "Loading…"** and the `/#build` link lands on the wrong part of the page.
2. **The library makes you pass four layers of filters** before the first result, and hovering a result erases the text you were reading.
3. **The words do not match the thing.** Prompts and minds carry skill buttons, six workflows show skill buttons, "305 of 305 ready" sits next to "the rest are being built".
4. **Browser-native pieces break the crafted feel**: nine `confirm()` and `prompt()` dialogs, three native selects, toasts with no undo.
5. **Small grey text fails the contrast bar** on the labels that carry the structure (kind, counts, kickers, metadata).

Fix those five and the site is impeccable. The "fun" list at the end is what turns a clean site into one people show their friends.

## What was checked

- Source: `site/src` (App, Library, BlockPage, Builder, BuilderParts, ui, Install, DownloadDialog, MindsPage, ToolsPage, HowItWorks, IntakePage, SpacePage, Comments, styles.css, tools.css), `index.html`, brand rules in `brand/COPYWRITING.md` and `brand/CHECKLIST.md`.
- 40 screenshots at desktop and phone width, dark and light.
- Behaviour probes with Playwright: load timing, hover behaviour, tab stops, text sizes, deep-link scroll position, block page structure.
- Catalogue stats from `public/data/blocks.json`.

## Findings and fixes, ranked

### P0. Things a visitor hits in the first minute

**1. Deep links show a bare "Loading…" line with the footer under it.**
Every route except home renders `<p class="small">Loading…</p>` until the 1.9 MB catalogue arrives, so a shared skill link opens on an almost empty dark page (`App.tsx` Suspense fallback and the `c` null checks in each page).
Fix: ship a per-slug page file (they already exist in `public/data/pages/*.json`) and render the block page from that file first, loading the big catalogue only for the library. Draw a skeleton that matches the final layout (kicker, title bar, three button pills, gauge box) so the page does not jump. Split the catalogue into one file per kind or per area so the library can draw the first 12 cards from a 50 KB slice.

**2. `/#build` and `/#library` land in the wrong place.**
The browser scrolls to the hash before the library renders, then the library grows by about 1,900 px and pushes the builder away. Measured landing: 2,400 px, builder at 4,313 px.
Fix: give the builder its own route (`/build`) and the library its own (`/library`) so the header links work from every page, not only home. If anchors stay, re-scroll to the hash after the catalogue has rendered.

**3. The hero never says what this is.**
"Use AI like the top 1%" plus a typed line is a mood, not a promise. Nothing on the first screen says free, 4,000 ready-made prompts and skills, or what a block is. On the phone the headline starts 600 px down with empty space above it (`m-home.png`).
Fix: one line under the headline that states the offer, for example "4,067 free prompts, skills and workflows you add to Claude, ChatGPT or Gemini once and start by name." Add a four-tile strip under the hero for the ladder (prompt, skill, workflow, agent) with one sentence each and a count, so the words used everywhere else are explained once. On the phone, pin the headline to the top third.

**4. Logo blanks between builds.**
The animated mark goes empty for about 380 ms between block builds, which caught two screenshots with no logo (`d-minds.png`, `m-build-tpl.png`).
Fix: cross-fade the next build over the last one, or leave the finished block in place and only animate on hover and page change.

### P1. The library

**5. Four filter layers before the first card.**
Search, 11 area chips, 30 function cards in a two-row horizontal scroller (8 visible, 22 behind arrows), sub-job chips, then 5 kind tabs and two selects. On a phone the first card is three screens down (`m-library.png`).
Fix: make search the hero of the library and the only thing above the fold with the results. Move areas and kinds into one compact filter row with counts, and move the 30 functions into a "Browse by job" drawer or a second-level panel that opens from the area chip. Show the first 12 cards immediately under the search box. Remember the last filter in the URL (`/library?area=marketing&kind=skill`) so people can share a view and the back button works.

**6. Hovering a card erases the summary.**
`Peek` resets to zero characters and retypes on every mouse enter (probe: 87 characters to 20). The "View the skill" line also flickers through 0 and 1. People hover to read, and the text disappears under them.
Fix: type once when the card first enters the viewport, then hold. On hover, change only a small thing (dither corner, arrow slides right, kicker brightens). Keep the typing effect for the hero and the builder preview, where it means something.

**7. Searching greys out the whole filter wall instead of hiding it.**
"refund email" returns one result, but the 30 function cards stay on screen at zero opacity and the area chips show eleven zeros (`d-search.png`). The result sits below a screen of dead UI.
Fix: when a search is active, collapse the function scroller and show only chips with a count above zero. Show results count and the matching kinds next to the search box. Add "did you mean" suggestions from block names for zero-result searches.

**8. Card bodies are uneven.**
2,222 summaries break the 18-word rule and 294 names break the 7-word rule, so cards vary between 3 and 6 lines and the grid looks ragged (`d-library-full.png`). The kicker and area label on the right wrap under each other when the area name is long ("Run meetings, notes and plans").
Fix: clamp the summary to three lines on cards with an ellipsis, and run a copy pass to bring summaries under 18 words (the rule already exists in `brand/COPYWRITING.md`; a script can flag them). Put the area label on its own line under the kicker so it never wraps into the title.

**9. Keyboard path is 69 tab stops to the first card.**
Fix: add a "Skip to results" link after the search box, make each chip group a single tab stop with arrow keys inside (roving tabindex), and give the function cards the same.

### P1. Block pages

**10. Prompts and minds wear skill clothes.**
A prompt page shows "Add it to your AI", "Copy the skill" and "Want this skill tailored for you?", while the How it works page says prompts are pasted each time (`d-skill-light.png`). A mind page shows the same four buttons plus the "Thinking it needs" gauge (`d-mind.png`). Six workflows with no steps show skill buttons under a workflow kicker (`copy-winning-ad-layout`).
Fix: one action set per kind.
- Prompt: "Copy the prompt" (primary), "Save to kit", "Add to a workflow". No install dialog.
- Skill: as today.
- Workflow: "Download the workflow", "Open in the builder". For the six without steps, either give them steps or file them as skills.
- Mind: "Talk to [name]" (primary, copies the persona), "Add to a council", "Save to kit". Replace the gauge with "Best for" lines.
Wire the labels from `kindOf(b)` so this cannot drift again.

**11. The hero gives the thinking gauge more weight than the deliverable.**
666 px of hero before the first section; the gauge box is the largest element on the first screen (`d-skill.png`). The "What you'll get" skeleton, which is the thing people came for, starts at 803 px.
Fix: cut the hero to kicker, title, one-line summary, buttons, and a single meta row (level, tested, thinking as a small pill). Put "What you'll get" on the first screen, right of the title on desktop. Move the gauge into the "Before you start" section.

**12. 10,000 px and 14 sections is too long for a page about one skill.**
Related lists (Who can help, Part of these workflows, Works best with, What to do next) each add a full card grid.
Fix: collapse secondary sections into accordions that open on click, and show related items as a single compact row of chips with counts. Make the TOC sticky with the current section highlighted (it is sticky but does not track). Target under 4,000 px for a typical skill.

**13. The right-edge "Questions" tab and the top-right "Want this skill tailored for you?" link compete with the actions.**
On the phone the Questions tab is a floating pill that covers the gauge text (`m-skill.png`).
Fix: fold Questions into a normal section at the end with a count in the TOC, and make the tailored link a quiet line under the buttons ("Need it for your business? Ask for a tailored version").

**14. "Add it to your AI" explanation is 4,351 px down.**
The install tabs (Claude, Claude Code, ChatGPT, Gemini, Other) are good, but a first-time visitor who clicks the primary button sees a dialog and does not learn why installing beats pasting.
Fix: one sentence in the dialog header: "Install once, then type its name in any chat. No pasting." Keep the chosen tab across pages (already done with `abb:install-tab`) and show it as a small pill on the button: "Add it to Claude".

### P1. Builder

**15. Loading a template does not fit the view.**
After picking "Test two ads head to head", the third node is cut at the right edge and the step panel covers the view controls (`d-build-tpl.png`, `d-build-step.png`).
Fix: call fitView after a template loads and after "Lay out the steps". Move the view controls to the bottom-left so the step panel never covers them. Give the stage a minimum height of 560 px instead of 78vh so it works on short laptop screens.

**16. "More" hides the saved workflows in a native `<select>`, and Delete uses `confirm()`.**
Fix: a proper popover listing saved workflows with name, step count and date, plus rename and delete inline. Delete shows an undo toast for five seconds instead of a dialog.

**17. Share falls back to `window.prompt`.**
Fix: a share sheet with the link in a copy field and a QR code for phone hand-off.

**18. The empty state is good, make it the demo.**
The goal box with three examples is the clearest "aha" on the site. Add a "Try one" button that lays out an example workflow and runs the Preview animation once, so a visitor sees the whole idea in five seconds without typing.

### P1. Minds, tools, other pages

**19. "305 of 305 ready. The rest are being built."**
Both lines show at once (`d-minds.png`). Fix: hide the second line when the first is complete.

**20. The face wall has no names until hover.**
305 faces in a 17-wide grid are striking but unreadable, and on the phone they are 50 px squares with no label. Fix: show a name tooltip on hover (desktop) and a name under the face on tap (phone); add a type-ahead "Find a mind" box above the wall; highlight the faces that match the chosen area and dim the rest instead of removing them, so the wall keeps its shape.

**21. Tools are the best pages on the site. Two small things.**
The kicker pill wraps into two lines on the phone ("discount / calculator", `m-tool.png`). Fix: keep kickers under 16 characters or let the pill shrink its text. The tools index cards misalign where the kicker is long ("order margin and break-even"). Fix: same rule.

**22. Intake and Space use native selects and plain forms.**
`IntakePage.tsx` and `SpacePage.tsx` use `<select>` and four `confirm()` calls. Fix: use the `Select` component from `ui.tsx` and the undo toast pattern.

**23. The Download dialog hugs the top-left corner.**
It renders at 0,0 with no margin over the header (`d-download.png`). The checklist with "0 of 5 ready" reads as a gate, but the download button is enabled anyway. Fix: centre the dialog, and either gate the button on the checklist or change the copy to "Tick what you have, the rest gets MISSING".

### P2. Polish and accessibility

**24. Contrast.** `--faint` is 3.31:1 (light) and 3.88:1 (dark). Raise it to about `#6b6b6b` light and `#8c8c8c` dark (both over 4.5:1 against the backgrounds), and keep `--muted` for body copy.

**25. Text size.** Raise the floor to 12 px for anything a person has to read (kind, count, kicker, meta, TOC). 10.5 px mono is fine for decorative labels like the gauge ends.

**26. Theme default.** `index.html` sets dark first; the comments in `styles.css` and `ThemeToggle` say light first. Pick one and remove the other note. Respect `prefers-color-scheme` on first visit.

**27. Loading states.** Replace every "Loading…" with a skeleton that matches the page. Add a thin progress bar at the top for the catalogue fetch.

**28. Toasts.** 2,600 ms with no undo. Add "Undo" to every destructive toast and let people dismiss by click.

**29. Drawer focus.** Drawers move focus in and close on Escape but do not trap focus, so Tab leaves the drawer and lands behind the overlay. Add a focus trap and return focus to the opener on close.

**30. Three containers, one job.** Kits, saved workflows and My space all hold "things I keep". Newcomers meet "About me", "My kits", "My space" in the header with no explanation. Fix: one "Mine" menu in the header with three rows (My file, My kits, My workflows) and a one-line hint on first open. Rename the About me drawer title to "My file" and keep the inside as is.

**31. Header labels on other pages.** "Library" and "Builder" are anchors on home only. From a skill page they jump to home and then scroll. Routes (item 2) fix this.

**32. Apps page.** The embedded Mercatura example uses a serif, blue, light design that looks like a different company (`d-apps.png`). Frame it with a caption bar ("Example app built from these skills, click through, no sign-in") and a hard-shadow border so it reads as an exhibit, not a broken theme.

## Fun: what would make people smile

These are additions, after the fixes above. Each one uses a thing the site already has.

1. **Hero that builds itself.** Instead of the typed lede, animate three blocks snapping together into a workflow (the logo animation at hero size), then the headline resolves with the decode effect. Five seconds, once per visit.
2. **"Try one" on the builder.** A one-click demo that lays out a three-step workflow and runs the bits animation through it, ending on "Download the workflow".
3. **Card personality.** Each kind gets a tiny pixel glyph that animates once on first view (a prompt blinks, a skill clicks into place, a workflow draws its arrows, an agent's eye scans, a mind's face tilts).
4. **Council arguments on the minds page.** Seat three minds and show a 3-line scripted "argument" preview in the council bar before the person downloads anything.
5. **Progress on the ladder.** A small "Your ladder" badge in the header that fills as a person copies a prompt, installs a skill, downloads a workflow. No account needed, it lives in localStorage like everything else.
6. **Keyboard delight.** `/` already focuses search. Add `j`/`k` to move between cards, `Enter` to open, `s` to save to kit, `?` to show the map. Show the keys as pixel caps in a tiny footer hint.
7. **Sound off by default, one click on.** A soft click on block snap and a short tick on typed text, with a toggle next to the theme switch.
8. **Share cards.** When someone shares a skill link, the open-graph image is a rendered card in the site's style with the pixel icon, name and summary.
9. **Calculators that talk back.** The answer bar already explains the sum. Add one playful line when the numbers are extreme ("At 60% off you'd need to sell 150% more. That is a fire sale.").
10. **Empty kit.** When "My kits" opens empty, show a pixel shelf with a dotted outline and "Your first kit goes here. Save any block to start."

## Suggested order of work

1. Week 1: items 1, 2, 4, 10, 19, 23, 24, 26 (routes, page-file rendering, skeletons, label fixes, contrast). These are mostly code, no design needed.
2. Week 2: items 5, 6, 7, 8, 11, 12 (library and block page restructure). This is the biggest change to how the site feels.
3. Week 3: items 15 to 18, 20, 30 (builder polish, minds wall, one "Mine" menu).
4. Then the fun list, starting with 2 and 3.

## What this audit did not cover

- Real network timings on a phone; only a local server was measured.
- Screen reader runs; only tab order and contrast were probed.
- Spaces and comments with a live server function; only the empty states were seen.
- The Mercatura example app itself.
