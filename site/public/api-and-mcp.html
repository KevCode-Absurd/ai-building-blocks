API & MCP guide

Connect with API & MCP.

Connect a supported AI once, then call your personal or company workflows and skills by name. Your AI reads their saved instructions and text files, then runs the authorized work with its own tools.

01

Choose the work your AI can read

MCP is a way to connect an AI to tools and files. Add one of these server URLs in your AI tool's connection settings.

Public library

Find skills for a new task

Search published skills and build a workflow in your AI. Public access does not need sign-in.

https://useaiblocks.com/mcp

Your saved work

Reuse your saved workflows

Read your account's saved skills, workflows, kits and profiles. Sign in to AI Blocks when your AI asks.

https://useaiblocks.com/mcp/personal

Your company Space

Use your team's saved work

This URL opens your own Space. To read another company Space, use the full URL its owner gives you.

https://useaiblocks.com/mcp/company

For a selected company Space, the owner gives you a URL ending in /mcp/company/{connection-token}. You must also sign in with an allowed work account. The owner controls access.

For private work, choose OAuth sign-in and automatic client registration (DCR). Use a separate connection for personal and company work.

02

Add the connection to your AI tool

Your app needs remote MCP over Streamable HTTP. Its plan and workspace settings must allow custom connections. The skills you run may also need files, a browser or other tools.

CodexCompany workflow tested

Add your personal library, then sign in:

codex mcp add ai-blocks-personal --url https://useaiblocks.com/mcp/personal --oauth-resource https://useaiblocks.com/mcp/personal --oauth-client-registration dcr
codex mcp login ai-blocks-personal --scopes saved:read --oauth-client-registration dcr

For company work, use its full URL, a different name and company:read. For public skills, add https://useaiblocks.com/mcp without sign-in. Check your installed CLI's help for the flags it supports.

03

Call your saved workflows and skills

After connecting ChatGPT, Claude or another compatible AI, choose a prompt below. Replace the brackets with your saved name or ID and task. A fresh chat needs that name or ID because it may not know your earlier conversation.

Personal workflow: first run

Use my AI Blocks personal connection to find “[workflow name or saved ID]”. Read its full saved workflow, attached skills and required files. Show the IDs, versions, chosen skills and blockers. My task is [task]. Keep its saved steps and dependencies. Ask for missing required facts and approvals, then run the authorized work with your tools and report the actual checks.

Personal workflow: fresh chat

Use my existing AI Blocks personal connection to run “[workflow name or saved ID]” for [new task]. Retrieve its current steps, attached skills and required files. Compare with [last version, if available] and show changes before running. Keep the saved structure, resolve missing inputs and approvals, then execute and check the authorized work.

Company workflow: first run

Use my AI Blocks company connection for “[company Space]” to find “[workflow name or saved ID]”. Retrieve its full steps, mapped skills, profiles and required files. Show the chosen items, versions and blockers. My task is [task]. Ask for missing required facts and approvals, then run the authorized steps with my tools and check the results.

Company workflow: fresh chat

Through my existing AI Blocks company connection for “[company Space]”, run “[workflow name or saved ID]” for [new task]. Read the current saved workflow and its skills and files. Compare with [last version, if available] and show changes. Keep its structure, resolve required inputs and approvals, then execute and verify the work.

Saved skill: first use

Use my AI Blocks [personal or company] connection to find the saved skill “[skill name or saved ID]”. Read its full instructions and every required reference through the connection. Show its ID, version and required inputs. Apply it to [task] with my authorized tools, ask for anything missing, and report the result and actual checks.

Saved skill: fresh chat

Use my existing AI Blocks [personal or company] connection to load “[skill name or saved ID]” again for [new task]. Read its current instructions and required files. Show any change from [last version, if available], resolve required inputs and approvals, then apply the skill and check its output.

Your AI retrieves the saved workflow, attached skills and supported text references automatically. Review the imported skills and versions before work begins. A standalone skill can be read and used directly; it does not need a new workflow.

Normal tool approvals or enabling an installed connector may still be needed in a fresh chat. Sign-in and company membership must stay valid. Expired or revoked access, a removed connector or a rotated company URL requires reconnecting. Device-only saves must first be synced in AI Blocks.

Bring the facts the job needs

Your brief, brand files or business data stay in the tools you authorize. Your AI asks for missing required facts.

Review the skills it chooses

For a new workflow, ask your AI to propose steps and skills. Choose replacements or edits before it prepares the plan.

Keep changes in your AI

Ask for a replacement skill or local edit, review the revised plan and prepare it again before running affected steps. To save the edit back to AI Blocks, use the app's save controls.

04

Build the same connection into your app

The API lets your app find saved work, read its files and prepare it for your AI. Your app supplies the AI and the tools that do the job.

Try the public API

No account or API key is required for the public library. Search first, then use a returned slug and revision_sha256 to retrieve the full instructions.

curl 'https://useaiblocks.com/api/v1/search?query=writing&type=skill&limit=5'
const base = 'https://useaiblocks.com/api/v1';
const response = await fetch(`${base}/search?query=writing&type=skill&limit=5`);
if (!response.ok) throw new Error(`Search failed: ${response.status}`);
const { items } = await response.json();
if (items.length) {
  const { slug, revision_sha256 } = items[0];
  const skill = await fetch(`${base}/skills/${slug}?revision_sha256=${revision_sha256}`);
  if (!skill.ok) throw new Error(`Skill retrieval failed: ${skill.status}`);
  console.log(await skill.json());
}

Public REST reference

Method and pathPurposeArguments
GET /api/v1/statusCheck public API capabilities.None. Open status.
GET /api/v1/searchFind published skills and workflows.query, type, category, limit (1–25), offset. Follow next_offset until null.
GET /api/v1/skills/{slug}Read skill instructions and its file inventory.Optional revision_sha256 pins the selected version.
GET /api/v1/workflows/{slug}Read a workflow and its ordered skill references.Optional revision_sha256.
GET /api/v1/resources/{slug}Read a supporting text file.path, revision_sha256, optional offset and limit. Follow all chunks.
POST /api/v1/workflow-preparationsValidate a proposed workflow and prepare an unsaved draft.Send JSON with Content-Type: application/json. See the schema for the complete preparation body.

  • Keep OAuth tokens in your app's secure store. Send the access token in the Authorization header. It must belong to the matching MCP resource and user.
  • Private files use base64 byte chunks. Join them in order until next_offset is null. Check the full byte count and SHA-256 hash. Public text offsets count Unicode code points.
  • Keep the returned file and workflow versions. A change needs a fresh read and review. A prepared plan does not prove that a step ran.
  • Personal skills use list_saved_items with kind: "skill", then get_saved_item and get_saved_resource. Company skills use the matching company tools. Embedded personal skills include saved_origin to identify their workflow.
  • Each private MCP connection has four saved-work tools and the five public tools. Read tools/list for their exact schemas.

Open the public OpenAPI schema · Open OAuth server details

Your AI must have the tools and files required by each step. Missing required files or tools block that step. The connection reads saved text resources; private binary file storage is not supported yet.

The MCP tools read and prepare work. Your AI follows your permissions and the workflow's checks. Its subscription or API account pays for its work. AI Blocks still pays for ordinary API, database and sign-in infrastructure. Saving an item does not start a background run.

05

MCP tool reference

Use a remote MCP client with Streamable HTTP. The public server is https://useaiblocks.com/mcp. Connect through your client's MCP settings, then use tools/list to discover the current argument schemas.

ToolWhat it returns
search_libraryPublic catalogue matches, slugs and revision hashes.
get_skillFull skill instructions and supporting-file inventory.
get_workflowWorkflow definition, governing instructions and ordered skill references.
get_resourceA chunk of a supporting text file. Fetch every chunk before using the file.
prepare_workflowA validated draft for the host AI to review and run with your authorization.

Personal and company connections add four saved-work tools to these five public tools. Each private connection requires its own matching OAuth resource and scope. The connection reads and prepares work; it does not save edits or run steps on the server.

06

Troubleshooting

Response or symptomWhat to do
400 / invalid argumentsCheck the OpenAPI schema or MCP tool schema. Use the exact argument names and valid ranges.
401 / sign-in neededReconnect the private server through OAuth. Use saved:read for personal work or company:read for company work.
403 / access deniedCheck the signed-in account and company Space permissions with its owner.
404 / not foundSearch again and use the returned slug or saved item ID. Public and saved-work routes have different identifiers.
409 / stale revisionRetrieve the current version and review the changes before preparing the workflow again.
429 / rate limitedPause requests and retry with backoff. Avoid repeated parallel searches.
503 / unavailableRetry later. A failed retrieval does not mean the workflow ran.
Opening an MCP URL in a browser failsAdd the URL to an MCP client. It is a protocol endpoint; use this guide for human-readable documentation.
