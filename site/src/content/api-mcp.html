API & MCP guide

Connect your AI once, then pull any skill, workflow or tool it needs.

Add one connection to ChatGPT, Claude, Claude Code, Codex or your own app. Your AI can then find and load skills, workflows, agents, prompts, minds, AI tool guides and calculators when a task needs them. It loads only what it picks. That includes the public library, your saved work and your company's Space. Your AI does the work with its own tools.

Your AI account pays for its work. AI Blocks serves the skills, files and workflow plans.

Hire a specialist for a deliverable

Choose from the AI specialist roles, or ask your connected AI to call find_specialist with the task. Check the complete role's remit, capabilities and deliverables. Then call prepare_specialist with role_id, task and relevant context, tools, training or authorized me.

The result includes SOUL.md, knowledge, a playbook, method routing, connection and permission checklists, editable training/context and a task-specific launch brief. Your AI reads the full methods, verifies access, carries out authorized work and returns actual files and checks. The public service does not run a hosted worker or train a model.

API: GET /api/v1/specialists?task=..., GET /api/v1/specialists/{role_id} and POST /api/v1/specialist-preparations. Keep private task context in the POST body rather than a public discovery URL.

04

Build the same connection into your app

The API lets your app find saved work, read its files and prepare it for your AI. Your app supplies the AI and the tools that do the job.

Try the public API

No account or API key is needed for the public library. Search first. Each result has an id, type, page url and one line. Then get the one you want. Replies are short by default. Add response_format=detailed when you need the full instructions.

curl 'https://useaiblocks.com/api/v1/search?query=writing&type=skill&limit=5'
const base = 'https://useaiblocks.com/api/v1';
const response = await fetch(`${base}/search?query=writing&type=skill&limit=5`);
if (!response.ok) throw new Error(`Search failed: ${response.status}`);
const { items } = await response.json();
if (items.length) {
  const { id, type } = items[0];
  const item = await fetch(`${base}/items/${id}?type=${type}&response_format=detailed`);
  if (!item.ok) throw new Error(`Item retrieval failed: ${item.status}`);
  console.log(await item.json());
}

  • Keep OAuth tokens in your app's secure store. Send the access token in the Authorization header. It must belong to the matching MCP resource and user.
  • Private files use base64 byte chunks. Join them in order until next_offset is null. Check the full byte count and SHA-256 hash. Public text offsets count Unicode code points.

Your AI must have the tools and files required by each step. Missing required files or tools block that step. The connection reads saved text resources; private binary file storage is not supported yet.

The MCP tools read and prepare work. Your AI follows your permissions and the workflow's checks. Its subscription or API account pays for its work. AI Blocks still pays for ordinary API, database and sign-in infrastructure. Saving an item does not start a background run.

05

MCP tool reference

Use a remote MCP client with Streamable HTTP. The public server is https://useaiblocks.com/mcp. Connect through your client's MCP settings, then use tools/list to discover the current argument schemas.

Your AI builds a workflow in this order: search, plan the steps with plan_workflow, use a ready workflow if one fits, read the full instructions for the chosen steps only, put the steps in order so each one gets what it needs, then check the plan with prepare_workflow and fix its warnings. The server runs plain code. It never calls an AI model.

Replies are short by default, so your AI stays fast and cheap. It asks for response_format: "detailed" only for the items it will use.

ToolWhat it returns
search_libraryThe front door. Short rows for any kind of item: id, type, title, page url, one line and the Tested label. Filter by type, job, level, Tested or date. With a date and no words, it shows what's new.
plan_workflowA short step plan for a job: the best first steps, ready workflows that already do it, and what comes before and after the best step, with the input each one passes on. Give it a slug to map one step. Each item has a page link your AI can cite.
get_skillA skill's summary, inputs, outputs, how to use it, file list and the steps that usually come before and after it. Detailed adds the full instructions.
get_workflowA workflow's ordered steps and which step passes each input to the next, with a diagram your AI can show you. Detailed adds its instructions, step notes and a text outline.
get_itemAny item by id: an agent, prompt, mind, AI tool or calculator. AI tools show what they do, what they cost and when we last checked.
get_resourceA chunk of a supporting text file. Fetch every chunk before using the file.
prepare_workflowA validated draft for the host AI to review and run with your authorization. It warns when a step is missing an input or comes before the step that makes it. Give it the step ids in order (slugs) and it suggests changes with reasons: add, move, swap or remove a step. It returns a diagram and a link that opens the result in the builder.
search and fetchThe same library in the exact shape ChatGPT deep research and company knowledge look for, with links to cite.

Also on the same server

  • Prompts. Apps that support them show these as slash commands: Find a skill, Build a workflow, What's new, and ten ready workflows.
  • Skills. Apps that support the MCP Skills extension can list skills and load one only when needed, at skill://{name}/SKILL.md. Each file comes with its size and SHA-256 hash.
  • Resources. Any item at aiblocks://{type}/{id}, and every job id at aiblocks://jobs.
  • Discovery. Apps can find the server from /.well-known/ai-catalog.json and its server card.
  • Pages your AI can read. Every item page has a Markdown version and a JSON version: add .md or .json to its address, as in /skills/ad-angle-planner.md. New and changed items are in the JSON Feed and RSS feed.

Personal and company connections add four saved-work tools to these nine public tools. Each private connection requires its own matching OAuth resource and scope. The connection reads and prepares work; it does not save edits or run steps on the server.

Coordinate a specialist team

Start at Plan your AI team. Your AI reuses or builds the relevant brand brain/project brief, checks available tools, offers routes and proposes the smallest sufficient team. One specialist is valid for a narrow task.

  1. Use find_specialist for candidates. Read the selected worker and full methods at their exact revisions.
  2. Call prepare_specialist_team with the full plan: business id, goal, route options, stages, role ids, methods, dependencies, actual input/output artifacts, checks, context and action scopes. Show the returned PRD and diagram for review.
  3. Apply user edits and re-prepare. Report approval only for the exact reviewed plan_sha256. Changed plans and sources need fresh review.
  4. Your host AI executes with real authorized tools. Use checkpoint_specialist_team to validate reported artifacts, producer/consumer acceptances, required checks, blocked stages and resumable state. It does not execute or independently verify the host's evidence.

REST: POST /api/v1/specialist-team-preparations and POST /api/v1/specialist-team-checkpoints. The OpenAPI document describes the complete request schema. Public preparation is stateless, makes no model calls and grants no execution or live-action authority.

Save approved workflows and scoped memory

Authenticated personal and company connections can list, retrieve, explicitly save, update and export versioned workflows. The user must confirm a save to the selected business/workspace. save_workflow needs the template, expected version, idempotency key and explicit confirmation. Old read grants remain read-only; request a new consented read/write connection when saving is needed.

Private REST uses /api/v1/personal/workflow-records or /api/v1/company/workflow-records, with an optional selected company workspace id. Use the same selected scope for memory records and outcomes. Browser account sessions can use the new private routes after normal sign-in. API/MCP clients use their resource-bound OAuth grant. No client supplies or changes its own identity through a payload.

For reuse, call list_workflows for the matching business and task before drafting a new plan, then get_workflow_record. Retain accepted substitutions, excluded methods and current source revisions. export_workflow returns a verified complete ZIP or fails on stale/missing sources. A saved template is not automatic approval of a later run.

Use save_memory, list_memory and get_memory for dated, sourced preferences, corrections, brand context and decisions. Superseding guidance must stay within the same business and task scope. record_outcome links actual KPI evidence to a saved decision; unknown values cannot prove improvement. delete_private_record needs explicit confirmation and the current version. Keep credentials out of records.

Resume actual work

Use save_team_run, list_team_runs, get_team_run and export_team_run to retain the exact plan and validated host-reported checkpoint. REST uses /api/v1/personal/team-runs or the matching company route. Saves need write consent, expected version and idempotency key. Source and plan changes require fresh review. Run records are private and excluded from shared templates and ordinary workflow exports. Saving a run does not execute, independently verify or approve it.

Share deliberately

Call preview_workflow_share and show the exact sanitized projection. Only after user approval call share_workflow with its projection digest. The unlisted link omits private business context, goal, notes, memory, run records and tool permissions. Anyone holding it can read that displayed template until revoke_workflow_share succeeds. Private organization reads still require current membership.

Execution, learning and routines

The actual AI host reads only relevant current memory, performs the authorized work and preserves artifact/check receipts. Feedback can improve later work when it is really saved and retrieved; these files do not fine-tune a model or promise an error rate. A follow-up routine needs an actual supported scheduler/runtime, persistent checkpoint home, agreed trigger, permissions, limits and stop rules. No schedule is activated by preparing or saving a plan.
