Connect your AI

Connect your AI once, then pull any skill or workflow it needs.

Do it once in the AI you already use. After that, your AI can find a skill or workflow here and use it when a job needs one. Your AI does the work, and your AI account pays for it.

From a problem to work your AI carries through

Describe the result you want and what must stay healthy: lower acquisition cost while protecting order value and profit, a faster application without broken behavior, or fewer support delays without weaker answers. Your AI reuses context, checks the evidence, investigates the problem and ranks specific recommendations.

Choose the recommendation IDs you want to pursue. Your AI passes those choices, their prerequisites, source evidence, requested files and checks to the next orchestrator. It prepares the execution plan and carries out the covered work with your tools. Missing access leads to help with a connection or export, or a usable draft or patch with the remaining integration clearly identified. Actual implementation, experiment results and feedback stay visible.

Work runs in your connected AI using its model and tokens. Keep business files in your authorized local project or the host artifact system by default. Remote saved records are optional and require the existing explicit authorization.

To run the whole job, your AI calls start_outcome with your own words. It asks you one batch of questions. Then it looks up how experts do this kind of job, on the web and in our library. It builds a plan from our specialists and skills. We check the plan before you see it. You approve it before any work starts. Each step then comes back with instructions for the specialist doing it. You make every decision, and nothing goes live without your yes. The job's files stay in your project, so any AI can pick it up later.

Try the public API

No account or API key is needed for the public library. Search first. Each result has an id, type, page url and one line. Then get the one you want. Replies are short by default. Add response_format=detailed when you need the full instructions.

These GET requests work from any web page, a server or a script. Each reply has an ETag. Send it back as If-None-Match and you get a short 304 reply when nothing changed. Every error looks the same: { "error": { "code": "…", "message": "…" } }. The message says what to fix.

curl 'https://useaiblocks.com/api/v1/search?query=writing&type=skill&limit=5'
// Runs in a browser on any site, or in Node 18 and later. No key needed.
const base = 'https://useaiblocks.com/api/v1';
async function getJson(url) {
  const response = await fetch(url);
  const body = await response.json();
  if (!response.ok) throw new Error(`${response.status} ${body.error.code}: ${body.error.message}`);
  return body;
}
const { items } = await getJson(`${base}/search?query=writing&type=skill&limit=5`);
if (items.length) {
  const { id, type } = items[0];
  console.log(await getJson(`${base}/items/${encodeURIComponent(id)}?type=${type}&response_format=detailed`));
}

MCP tool reference

Use a remote MCP client with Streamable HTTP. The public server is https://useaiblocks.com/mcp. Connect through your client's MCP settings, then use tools/list to discover the current argument schemas.

Your AI builds a workflow in this order: search, plan the steps with plan_workflow, use a ready workflow if one fits, read the full instructions for the chosen steps only, put the steps in order so each one gets what it needs, then check the plan with prepare_workflow and fix its warnings. The server runs plain code. It never calls an AI model.

Replies are short by default, so your AI stays fast and cheap. It asks for response_format: "detailed" only for the items it will use.

Also on the same server

  • Prompts. Apps that support them show these as slash commands: Find a skill, Build a workflow, What's new, and ten ready workflows.

Use the uri that skills/list gives: {name} is the skill's own name, which is usually its id. Its other files are at skill://{name}/{path}, and each file comes with its size and SHA-256 hash.

Troubleshooting

Response or symptomWhat to do
400 / invalid argumentsCheck the OpenAPI schema or MCP tool schema. Use the exact argument names and valid ranges.
401 / sign-in neededReconnect the private server through OAuth. Use saved:read for personal work or company:read for company work.
403 / access deniedPublic library: origin_forbidden means a web page sent a request only apps may send. GET requests work from any page. Send MCP and POST requests from your server or app. host_forbidden means use https://useaiblocks.com. Private routes: check the signed-in account and Space permissions with its owner.
404 / not foundSearch again and use the returned slug or saved item ID. Public and saved-work routes have different identifiers.
409 / stale revisionThe item changed after the version you chose. The error lists the changed files and the current revision_sha256. Get the item again and review those changes before you prepare the workflow again.
429 / rate limitedWait the number of seconds in Retry-After, then try again. Searches and reads have a bigger allowance than workflow checks and outcome calls. On MCP the same error comes back as a JSON-RPC error.
503 / unavailableRetry later. A failed retrieval does not mean the workflow ran.

Follow the work from source to deliverable

Execution policy v2 records which current sources were inspected, which facts were inferred or missing, and why each selected AI Blocks method fits the task. The source-use trace includes exact revisions, complete resource hashes and retrieval receipts. It distinguishes reading a method from executing it on the current output. Unused specialist methods need not be loaded.

The alternative decision record compares frozen proposals against the same acceptance criteria, retains dissent and an alternative, and explains compatibility when combining ideas. An unknown stays unknown; a known critical failure cannot be hidden by an average score.

Before native production, the host reports its actual available tools with recent check receipts. Missing capabilities block production. Marketplace get_execution_plan and POST https://agents.useaiblocks.com/api/execution-plan accept an optional host_tools inventory and return native_preflight. These read-only checks invoke no tools or models and authorize no paid usage. A long-running team job can record refresh_capabilities without rewriting its earlier history.

Download the local artifact checker for real file-hash, image-decoding and bounded offline page-interaction checks. Read its setup guide; it does not run application builds or judge brand fidelity. On Your council, open a returned job-state JSON file to see reported sources, method use, alternatives and checks locally. The viewer neither uploads the record nor certifies it.

Save reviewed personal judgment

On an enabled authenticated connection, discover list_expert_records and the related profile, agent and capture tools alongside the existing library tools. Review a proposed lesson, edit or narrow it while unreviewed, then accept or reject its exact preview digest. Acceptance saves the revised agent and review atomically; rejection leaves the agent unchanged. Save receipts identify the actual destination, versions and hashes. No model weights are trained.

The same operations are available through POST /api/v1/personal/expert-agents or the matching company route, with {"name":"tool_name","arguments":{...}}. Use the existing resource-bound OAuth grant or same-origin signed-in account session. Writes need the matching consent and current versions. export_expert_record provides private portable JSON; explicit exact-record deletion removes its history, refuses dependent records and prevents retries resurrecting it. Personal saving never publishes an agent.

start_outcome and start_job expose an execution_plan. Outcome and team-job planning files include EXECUTION-PLAN.json; a direct specialist route can return the plan without creating that file. Your AI scopes these requirements against your request, reads the relevant AI Blocks methods and does the work with its actual tools.

A request to build a landing page means editable website source unless you ask for a design reference. The team inspects the existing site and records what it reuses, the integration target, authentic fonts and assets, build and preview commands, and checks of the primary action, links, assets, phone and desktop layouts, and keyboard access. Reports are tied to the current source hash. A page image cannot satisfy this contract.

Team production submits landing_page_delivery; outcome production submits it with production_artifacts. See the landing-page delivery schema. These checks validate host-reported evidence. They do not independently inspect private files, run a browser, certify visual quality, or prove conversion improvement or customer approval.

Improvement and assessment work also uses ai-blocks-work-context/1: inspected current sources, dated snapshot hashes and freshness basis, what must stay true, source-backed changes and baseline-to-result observations on the delivered revision. This applies to nonvisual work too. A planned comparison is not a completed check.

Static-image outcomes use the visual-delivery report. A bundle lists its individual child artifacts and hashes; the ZIP hash does not replace those outputs. The optional local file-evidence adapter verifies bytes when installed in the host. It does not judge semantics. Owner acceptance and business outcomes remain separate.

Task and approved brand requirements take precedence over specialist presentation preferences and a conditional neutral fallback. Existing facts, source rights and action permissions remain independent requirements. Personal corrections stay scoped; a correction to one artifact does not ban an entire format.

New job state uses ai-blocks-job-state/2; new outcome engagement uses ai-blocks-outcome-engagement/3. Older records remain readable as legacy records with their original, weaker checks. Starting a new run applies the current requirements.

Coordinate a specialist team

Start at Plan your AI team. Your AI reuses or builds the relevant brand brain/project brief, checks available tools, offers routes and proposes the smallest sufficient team. One specialist is valid for a narrow task.

  1. Use find_specialist for candidates. Read the selected worker and full methods at their exact revisions.
  2. Call POST /api/v1/specialist-team-preparations (or prepare_specialist_team on a signed-in connection) with the full plan: business id, goal, route options, stages, role ids, methods, dependencies, actual input/output artifacts, checks, context and action scopes. Show the returned PRD and diagram for review.
  3. Apply user edits and re-prepare. Report approval only for the exact reviewed plan_sha256. Changed plans and sources need fresh review.
  4. Your host AI executes with real authorized tools. Use POST /api/v1/specialist-team-checkpoints (or checkpoint_specialist_team on a signed-in connection) to validate reported artifacts, producer/consumer acceptances, required checks, blocked stages and resumable state. It does not execute or independently verify the host's evidence.

The public MCP server lists start_outcome as the front door instead of these team tools. The OpenAPI document describes the complete request schema. Public preparation is stateless, makes no model calls and grants no execution or live-action authority.

Review current work without a forced rewrite

An inspected current artifact may already meet the accepted job. Full review can retain its exact files; it need not invent a flaw, combine every proposal or rewrite passing work. Explicit requests for exploration, variants or redesign still control. Preserve approved invariants without treating all existing wording as immutable.

For an unchanged IMPROVE result, use the optional work_context.retention record in the published current-work schema. An empty change list alone is insufficient. Map every retained file to its inspected CURRENT baseline hash, record the original-request review and observations for every actual accepted criterion, and deliver the exact path/hash set. Pending or failed criteria, missing acceptance, stale sources or changed files block retention at production. Existing native checks and independent review still apply. Outcome criterion IDs follow done-0, done-1 and the current brief order. These are host-reported records, not independent semantic verification, owner approval or a measured quality gain.

Save approved workflows and scoped memory

Authenticated personal and company connections can list, retrieve, explicitly save, update and export versioned workflows. The user must confirm a save to the selected business/workspace. save_workflow needs the template, expected version, idempotency key and explicit confirmation. Old read grants remain read-only; request a new consented read/write connection when saving is needed.

Private REST uses /api/v1/personal/workflow-records or /api/v1/company/workflow-records, with an optional selected company workspace id. Use the same selected scope for memory records and outcomes. Browser account sessions can use the new private routes after normal sign-in. API/MCP clients use their resource-bound OAuth grant. No client supplies or changes its own identity through a payload.

For reuse, call list_workflows for the matching business and task before drafting a new plan, then get_workflow_record. Retain accepted substitutions, excluded methods and current source revisions. export_workflow returns a verified complete ZIP or fails on stale/missing sources. A saved template is not automatic approval of a later run.

Use save_memory, list_memory and get_memory for dated, sourced preferences, corrections, brand context and decisions. Superseding guidance must stay within the same business and task scope. record_outcome links actual KPI evidence to a saved decision; unknown values cannot prove improvement. delete_private_record needs explicit confirmation and the current version. Keep credentials out of records.

Share deliberately

Call preview_workflow_share and show the exact sanitized projection. Only after user approval call share_workflow with its projection digest. The unlisted link omits private business context, goal, notes, memory, run records and tool permissions. Anyone holding it can read that displayed template until revoke_workflow_share succeeds. Private organization reads still require current membership.

Execution, learning and routines

The actual AI host reads only relevant current memory, performs the authorized work and preserves artifact/check receipts. Feedback can improve later work when it is really saved and retrieved; these files do not fine-tune a model or promise an error rate. A follow-up routine needs an actual supported scheduler/runtime, persistent checkpoint home, agreed trigger, permissions, limits and stop rules. No schedule is activated by preparing or saving a plan.
