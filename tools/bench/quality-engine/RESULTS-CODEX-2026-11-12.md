## Ten changes, refined in v3.2

1. Deliver the native artifact: the requested email, table, template or decision appears first. Edit the plain draft's useful content and preserve its operating detail.
2. Preserve requested fill-in and merge fields, while rejecting internal notes and invented actual results.
3. Require a fresh anonymous final reader. Require no material loss of usefulness or clarity; usefulness breaks a clarity tie. Freeze the chosen bytes.
4. Detect broken Markdown table headers, delimiters and row widths.
5. Keep scope fixed. A pricing experiment cannot quietly change packaging or add unrequested commercial terms.
6. Make support replies usable with known order fields and only indispensable customer questions.
7. Match brand voice to the actual channel rather than adding generic cheerful language.
8. Check that comparisons, denominators, metrics and time horizons answer the requested decision.
9. Put usable copy before necessary setup notes; remove the default preamble for self-explanatory work.
10. Check brief-derived counts, headings, links, table fields and limits, binding each mechanical receipt to file and contract hashes. Exact heading text and table headers are required only when the request specifies them.

The shared method, downloadable packs and model-free job context carry these changes. The six check tools are portable resources; the host runs them. The service adds no hosted model execution or feedback endpoint.
