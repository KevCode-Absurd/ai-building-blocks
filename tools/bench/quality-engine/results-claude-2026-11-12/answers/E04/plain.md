Here's a set that sticks to your limits and uses Linear's own terms (teams, cycles, issues). Titles are in sentence case. Each title starts with a verb so the list reads as a sequence.

| # | Title (max 5 words) | Description (max 14 words) | Button (max 3 words) |
|---|---|---|---|
| 1 | Invite your teammates | Bring in the people you work with so every issue has an owner. | Invite people |
| 2 | Create your first team | Teams hold the issues, workflow and cycles for one group of people. | Create team |
| 3 | Import your existing issues | Move your backlog from Jira or GitHub so you start with real work. | Start import |
| 4 | Set up your first cycle | Plan work in time-boxed periods. Unfinished issues move to the next cycle. | Set up cycles |
| 5 | Connect GitHub | Pull requests link to issues by ID, and status updates as work merges. | Connect GitHub |
| 6 | Turn on Slack notifications | Send issue updates to the Slack channels your team already reads. | Connect Slack |

**Shown when everything is done:**

> Your workspace is set up. The rest is the work.

**Word counts (title / description / button):** 1: 3 / 13 / 2 · 2: 4 / 12 / 2 · 3: 4 / 13 / 2 · 4: 5 / 12 / 3 · 5: 2 / 13 / 2 · 6: 4 / 11 / 2

A few notes on the choices:

- **Item 3** says "existing issues" in the title rather than naming both tools. That keeps it to four words, and the description names Jira and GitHub. If you add more importers later (Asana, Shortcut), you only need to change the description.
- **Item 5** describes what the admin gets, not how to set it up. If you'd rather teach the habit up front, try: "Add an issue ID to a branch name and Linear links the pull request." (14 words)
- **Buttons** use the exact verb from each title where it fits ("Create team", "Connect GitHub"). That way the admin knows what will open before they click.
- **Completion line** has a backup if the first one feels too clever: "Setup is complete. Your workspace is ready for the team."
